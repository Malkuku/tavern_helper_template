## 产品定位与边界

“魔女恶堕计划”是故事中组织提供、未经用户主动安装而出现在手机上的 App。正文中的图标为深紫色，边缘有细微杂波；主角因交易被要求恶堕魔法少女并完成组织任务。

App 采用真实消费级会员产品的信息架构，承载组织相关能力：

| 区域 | 现有功能                             |
| ---- | ------------------------------------ |
| 任务 | 组织任务、候选任务、奖励领取与周进度 |
| 观测 | 统一角色观测：概览、身体、档案       |
| 商店 | 技能商店、道具商店                   |
| 我的 | 个人档案、已拥有技能、随身物品与仓库 |

微信、地图及普通手机应用保持独立。角色编辑器是创作入口，不进入组织 App。

底部导航为“首页 / 任务 / 观测 / 商店 / 我的”。首页以当前任务为主，不展示“已发现目标”摘要。页面只展示支持当前判断或操作的信息，不因变量存在就逐项展示。空状态按真实数据呈现，不用演示数据填充。

`系统.已发现目标`
为空时，桌面 App 图标以轻微抖动和向外扩散的粒子提示首次任务；点击 App 先进入观测页内的首位目标选择内容。该选择随页面滚动，不遮住整个手机。选定目标并完成原有正文日志和变量写入后跳转任务页；此后恢复常规首页入口与图标状态。

首页与任务页将每周完成至少 7 项任务明确标为必达 KPI，并提示完成后领取奖励才计入统计。进度条到 7 项即满，但累计计入数可以超过 7。个人档案的 user 评级使用带字母的风格化 SVG 徽章，未知评级保留“未记录”。

## 视觉与交互方向

- 整体感受为邪恶、妖艳、带情色暗示的深色会员 App。以黑紫、酒红与玫红或绯红高光形成品牌气质，同时保持正文、数值和操作的清晰层级。威胁和契约是叙事背景，不让日常页面变成恐怖警报界面。
- 参考 [Sephora Beauty Insider](https://www.sephora.com/ca/en/beauty/challenge-faq) 的会员任务、积分和兑换结构，以及
  [WHOOP 首页](https://www.whoop.com/us/en/thelocker/the-all-new-whoop-home-screen/)
  的指标概览到详情层级；参考结构，不复制品牌视觉或增加项目没有的业务机制。
- 高质量 SVG 用于品牌标志、图标、少量插画及数据图形；角色插画仅出现在少量重点位置。动态文字、按钮、表单、列表和导航使用 Vue/HTML/CSS，以支持响应式布局和真实交互状态。
- 动画用于 App 入场、页面切换、导航选中和新列表卡片出现，保持日常浏览流畅。任务、技能、道具刷新时依据各自已有的等待状态展示共用的旋转标记与无确定进度的流动条；成功、失败或取消后立即退出等待状态，不显示虚构的完成百分比。系统请求减少动态效果时停用这些动画。信息量与动画强度仍需在宿主视觉验收中校准。
- 任务候选、已接任务、首页当前任务、商店技能和已拥有技能以 D～S 单一评级呈现一致的等级外框：D 银灰、C 青绿、B 蓝、A 金、S 紫粉；等级越高光晕越明显，A/S 有轻微呼吸效果。技能的`适用评级`若不是明确的单一等级，保留普通外框，不从自由文本推断等级。减少动态效果时停止呼吸动画。
- 在宿主浏览器环境，App 根节点内的原生表单与交互控件须用有作用域的 `!important`
  覆盖关键前景色、背景色及正常、聚焦、激活、禁用状态，避免宿主样式和浏览器默认色污染；不得影响微信、手机系统或创作入口。

## 实施约束

- 魔法少女相关的未成年控制由角色卡总条目统一负责；编辑技能、任务、道具生成规则时，不重复添加局部年龄声明。
- 现有组织任务、角色观测、商店、档案与资产页面需按统一信息架构和视觉系统重构，不能仅套新外壳。
- 合并入口不改变各功能的数据权威来源与变量写回规则，不能复制业务逻辑。
- 未有数据契约支持的倒计时、自动惩罚、会员等级或其他业务规则不能仅为视觉效果加入。
- 正式实现需要在手机尺寸与 SillyTavern 宿主中验收排版、控件颜色、触屏、动效和状态变化；当前已有相关宿主联调项尚未完成。
