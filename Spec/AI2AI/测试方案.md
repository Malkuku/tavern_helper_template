# 测试方案

## 当前测试能力

仓库暂无专用单元测试框架或测试目录。现有自动化入口是 ESLint 和 Webpack 构建；Webpack 的 TypeScript loader 配置为
`transpileOnly`，因此构建成功不能替代完整类型检查或行为测试。

## 最小验证策略

- 魔法少女角色资源编辑：`scripts/validate-phone-role-editor.cts`
  覆盖已发展角色替换时默认保留完整阶段、显式阶段覆盖、非法等级、资源保存冲突及模板补全；`scripts/validate-phone-role-visual.cts`
  编译正式 Vue 组件，调用实际事件验证阶段描述、负经验、能力限制、身份、形态和列表编辑及结构往返。真实手机布局与世界书写入仍需宿主联调。

- 在场角色状态前端：本地 `ts-node` 执行
  `scripts/validate-present-status.cts`，验证共用手机真实组件、三项状态条、回退/满条、身体展开、解锁隔离、角色切换、缺字段、重试与卸载；手机宿主嵌入仍需联调。

### 当前环境的命令入口

当前 Windows 环境中的 `pnpm <script>` 会先执行依赖状态检查，并因
`@parcel/watcher`、`javascript-obfuscator`、`unrs-resolver`、`vue-demi` 的构建脚本尚未审批而报
`ERR_PNPM_IGNORED_BUILDS`。该错误发生在项目脚本启动前，不能作为代码验证结果。

当 `node_modules` 已存在时，验证统一直接调用本地可执行文件，不先尝试 `pnpm`，也不修改依赖审批配置：

```powershell
& ".\node_modules\.bin\ts-node.cmd" --project scripts/tsconfig.json --transpile-only scripts/validate-workshop.cts
& ".\node_modules\.bin\ts-node.cmd" --project scripts/tsconfig.json --transpile-only scripts/validate-scenario-data.cts
& ".\node_modules\.bin\ts-node.cmd" --project scripts/tsconfig.json --transpile-only scripts/validate-workshop-acceptance.cts
& ".\node_modules\.bin\webpack.cmd" --mode development
& ".\node_modules\.bin\eslint.cmd" .
```

只有在本地依赖不存在或确需更新时才处理安装；构建脚本是否获准执行属于环境安全配置，不由普通开发任务擅自改变。

- 纯数据解析：使用 Node 内置断言执行定向样例，覆盖变量标签、JSON
  Patch 的 insert/replace/delta/remove、数组追加和非法输入。
- 尘史使徒剧本组装：执行
  `npm run validate:scenario -- "<Beta 配置目录>"`，以真实配置覆盖旧地图迁移、完整嵌套地图组装、共享资源全量装配、角色有序覆盖、空任务和宿主失败回滚，并注入悬空 UUID、未知角色类型、缺少或重复
  `user` 等反例；组装结果不得重新产生已退出的顶层 `术` 能力表。
- 创意工坊实现自测：执行
  `npm run validate:workshop`，覆盖内嵌叙事无损往返、纯剧本 JSON 校验、十四套视觉方案、角色身份互斥、三类说话人精确解析、v2 包校验及旧分离格式拒绝、依赖闭包投影、冲突和仍存在的 UUID 重映射、角色字段及视觉
  `meta`、字段差异、安装预览，以及外部 AI 角色 JSON 流程。
- 地图相关迭代同时覆盖完整 SVG 安全子集、恶意 SVG 拒绝、多地图读取与剧本显式绑定、地图 JSON 往返、初始地点失效、资产包地图依赖闭包，以及 Beta 存量地图全部节点迁移。
- 创意工坊独立验收：执行
  `ts-node --project scripts/tsconfig.json --transpile-only scripts/validate-workshop-acceptance.cts`
  验证角色运行时事务、`user` 整体覆盖、包安装和旧机制退出；提供 Beta 配置目录时，再执行 `scripts/accept-workshop.cts`
  验证 5 个剧本、22 个角色、旧地图合并及角色编辑往返。
- 入口与模块收敛：运行 TypeScript/ESLint 静态检查，并检索旧导入、重复实现和删除文件引用。
- 跨入口改动：执行开发或生产构建，确认所有自动发现入口能够打包。
- Tavern Helper 宿主交互：在真实 SillyTavern 中检查浮层加载、消息更新、样式传送、路由切换和 `pagehide` 清理。
- 手机正文差分事务：运行本地 `ts-node` 执行
  `scripts/validate-mvu-patch-write.cts`，可附带原始正文文件路径；验证空货架的生成结果、刷新扣费和计次、购买后按正文顺序重算、JSON
  Pointer 和标签转义、无变化跳过、正文/变量失败回滚、读回不一致、取消及聊天/楼层切换。`scripts/validate-phone-system-log.cts`
  验证手机各业务入口的操作日志、资源差分和任务/阶段结算；真实 MVU 与 MvuHelper 的并发时序仍需宿主联调。
- 手机刷新回归：直接运行本地 `ts-node` 执行
  `scripts/validate-phone-failed-result-cleanup.cts`，覆盖失败标签清理重试、无事件的迟到结果、技能/道具/任务的手机与酒馆双向取消、排队结果取消、定向请求清除及中止导致的事件拒绝；禁用
  `crypto.randomUUID`
  验证定向入口，并编译三个真实页面验证事件未返回时取消后按钮恢复、立即重试及旧事件拒绝隔离。fixture 区分酒馆内置停止与助手停止按钮处理器，真实停止按钮与接口联动仍需宿主联调。附带
  `--user-floor`
  时在 user 最后一楼验证同一套结果上架、扣费计次、失败清理和取消保护；默认验证 assistant 楼层。`scripts/validate-phone-generation-result.cts`
  同时覆盖两种角色的同楼/后续楼层结果、旧结果与未闭合标签拒绝，以及系统楼层排除。
- 手机技能使用：直接运行本地 `ts-node` 执行
  `scripts/validate-phone-skill-use.cts`，通过编译后的技能页按钮验证草稿追加、原输入保留、`input`
  事件、最新技能作用、缺少启用字段的旧技能、关闭或已删除技能拒绝、输入框缺失提示，以及不修改技能变量。真实酒馆输入框交互仍需宿主联调。
- 手机道具：`scripts/validate-item-shop.cts` 与 `scripts/validate-phone-inventory.cts`
  覆盖生成价格优先、不同价格的同名购买/转移合并，以及随身/仓库丢弃和数量拒绝；`scripts/validate-item-ui.cts`
  编译正式 Vue 卡片与商店，覆盖 N/D/C/B/A/S 六档评级类、购买单价和数量总价、余额不足禁用、持有价格隐藏、丢弃来源、数量、二次确认和失败提示。`scripts/validate-phone-system-log.cts`
  同时验证丢弃日志、差分及写入失败撤回。评级光效和酒馆显示仍需宿主验证。可传入 `--items-only` 定向验收道具日志。
- 手机“设置 → 弹窗测试”可依次预览 Weline 消息、组织任务、低稳定度、三项人设阶段变化及三类刷新成功的顶部弹窗；预览不修改业务变量、已读状态或正式通知历史。正式阶段变化和刷新成功还需在宿主用 MVU 变化与生成结果验证触发及点击定位。

  编译正式 Vue 页面/添加组件，验证简洁浏览、详情、显式整理、多选、百张检索、旧格式表情、常用、归档、重名预检和账号/备份失败重试；结合具名表情、图片库、跨账号图片解析和会话楼层 ID 脚本回归。

  通过真实 Store 与正文事件入口验证负余额文字/表情添加、确认与入库、收退款仍负数时入账、余额不足付款失败保留缓冲、日志重放不重复结算、1 点兑换 100 日元、整数/余额校验、连续兑换最新余额和正文/变量失败回滚。编译正式组织 App 和兑换页验证商店兑换分类、输入校验、重复点击保护、成功/失败反馈；编译 Weline 和组织财务通知页验证钱包入口退出、假好友只读、名片/转发排除、无互动卡片，验证新通知未读/提醒与阅读不重复加钱。真实宿主仍需联调。
- Weline 浏览器验收：`node scripts/validate-wechat-sticker-browser.mts`
  用已安装 Webpack 编译正式组件与正式 CSS，用本地 Edge/CDP 验证 390/320 窄屏无横向溢出、首屏图片、普通浏览不显示选择框、整理/批量操作、百张搜索/详情、弹窗焦点循环、图库名称复用、真实 PNG 单图/多图添加和保存失败重试。截图保存在

  从 1200px 后台 iframe 将正式组件和手机 CSS 挂载到宿主文档，用 Edge 验证 390/320/280px 窄屏、横屏、超长图片、四种裁剪比例、宿主尺寸变化、拖动缩放及应用/原图/取消；截图保存在
  `.codex/previews/image-crop/`。不连接真实酒馆，不证明宿主上传与持久化。
- 本地 `.cmd` 启动文件损坏时，直接用 Node 调用已安装工具，例如
  `node -e "require('ts-node').register({project:'scripts/tsconfig.json',transpileOnly:true}); require('./scripts/validate-wechat-sticker-manager.cts')"`，不修改依赖审批。

## 已知限制

- 当前环境没有实际 SillyTavern 宿主自动化 fixture，无法自动证明 Tavern
  Helper 全局接口的运行时行为；Weline 表情组件可通过本地隔离 Edge fixture 验证。
- 创意工坊最终宿主验收仍需在真实 SillyTavern 中导入
  `dist/创意工坊/index.js`，确认全视口挂载、宿主样式隔离、世界书持久化与回滚、上传下载、MVU 角色写入、`pagehide`/收起生命周期、键盘焦点、窄屏布局和主要流程视觉截图。
- 所有 `pnpm <script>`
  在当前 pnpm 版本下都可能先触发依赖状态检查并失败；应按“当前环境的命令入口”直接调用本地可执行文件，除非包管理配置另行修复。

- 强制候选与固定刷新费：`scripts/validate-forced-quest-refresh.cts`，覆盖多次刷新、未接强制候选拦截、多项接取、字段移除、五项上限、放弃、跨周、余额与无效生成原子性、固定收费与定向附加费，以及 EJS 触发边界和全部五组范围。
