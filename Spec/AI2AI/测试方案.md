# 测试方案

## 当前测试能力

仓库暂无专用单元测试框架或测试目录。现有自动化入口是 ESLint 和 Webpack 构建；Webpack 的 TypeScript loader 配置为 `transpileOnly`，因此构建成功不能替代完整类型检查或行为测试。

## 最小验证策略

- 纯数据解析：使用 Node 内置断言执行定向样例，覆盖变量标签、JSON Patch 的 insert/replace/delta/remove、数组追加和非法输入。
- 尘史使徒剧本组装：执行 `npm run validate:scenario -- "<Beta 配置目录>"`，以真实配置覆盖旧地图迁移、完整嵌套地图组装、共享资源全量装配、角色有序覆盖、空任务和宿主失败回滚，并注入悬空 UUID、未知角色类型、缺少或重复 `user` 等反例。
- 创意工坊实现自测：执行 `npm run validate:workshop -- "<当前格式配置目录>"`，覆盖引用与可玩性检查、v2 包校验、旧格式明确拒绝、冲突和复制 UUID 重映射、角色字段及视觉 `meta` 无损往返、字段差异、安装预览，以及 AI 角色 JSON 解析、模板补齐和非法输出拒绝。
- 创意工坊独立验收：执行 `ts-node --project scripts/tsconfig.json --transpile-only scripts/validate-workshop-acceptance.cts` 验证角色运行时事务、`user` 整体覆盖、包安装和旧机制退出；提供 Beta 配置目录时，再执行 `scripts/accept-workshop.cts` 验证 5 个剧本、22 个角色、旧地图合并及角色编辑往返。
- 入口与模块收敛：运行 TypeScript/ESLint 静态检查，并检索旧导入、重复实现和删除文件引用。
- 跨入口改动：执行开发或生产构建，确认所有自动发现入口能够打包。
- Tavern Helper 宿主交互：在真实 SillyTavern 中检查浮层加载、消息更新、样式传送、路由切换和 `pagehide` 清理。

## 已知限制

- 当前环境没有自动化浏览器连接或宿主 fixture，无法自动证明 Tavern Helper 全局接口的运行时行为。
- 创意工坊最终宿主验收仍需在真实 SillyTavern 中导入 `dist/创意工坊/index.js`，确认全视口挂载、宿主样式隔离、世界书持久化与回滚、上传下载、MVU 角色写入、`pagehide`/收起生命周期、键盘焦点、窄屏布局和主要流程视觉截图。
- `pnpm lint` 在当前 pnpm 版本下会先触发依赖状态检查，并因被忽略的依赖构建脚本失败；验证应直接调用本地 ESLint 可执行文件，除非包管理配置另行修复。
