# 剧本数据组装契约

## 数据源

运行时数据来自当前角色主世界书中的以下禁用配置条目：

- `<开场白>配置`
- `<世界>配置`
- `<世界经济>配置`
- `<主线>配置`
- `<事件>配置`
- `<任务>配置`
- `<势力>配置`
- `<地图>配置`
- `<季节与节日>配置`
- `<开场文本>配置`
- `<种族>配置`
- `<角色>配置`

每个条目的正文必须是一个完整 JSON 文档。条目缺失、同名条目重复或 JSON 非法时，加载整体失败。

## 开场白与资源注册表

`<开场白>配置` 的根对象包含：

- `固定数据`：所有剧本共享的运行时状态基底。
- `开场白`：以 UUID 为键的开场白注册表。

开场白条目包含 `author`、`key`、`desc`、`可用`、`主题`、`图标`、`自定义主角` 和 `内容配置`。`内容配置` 是分类资源 UUID 清单：

- 单例引用：`开场文本`、`世界`、`地图`、`主线`。
- 集合引用：`角色`、`世界经济`、`季节与节日`、`势力`、`种族`、`任务`、`事件`。

编辑态允许引用暂时为空，但此时必须强制 `可用: false`。进入组装的可玩态剧本仍要求所有单例引用非空、所有 UUID 可解析。世界经济、季节与节日、势力、种族的 UUID 清单是底层同步缓存，读取与保存时同步为当前注册表全集，组装器始终直接使用全集。

## 组装规则

- `世界` 与 `主线`：UUID 定位条目后直接使用 `entry.data`。
- 任务与事件：按剧本 UUID 清单定位条目，以 `entry.key` 为运行时对象键，以 `entry.data` 为值。
- 世界经济、季节与节日、势力、种族：自动组装当前对应注册表全集，不以剧本清单作为事实源。
- `种族`：先以 `entry.type` 分组，再以 `entry.key` 为键写入 `entry.data`。
- `角色`：`type` 只允许 `user`、`主要角色`、`次要角色`；`user` 必须且只能引用一个。其余角色按有序 UUID 清单处理，同 `type + key` 后引用的完整 `data` 替换先引用，不做深合并。
- `地图`：地图资产结构为 `{ author, desc, data }`，`data` 直接是最终完整嵌套地图，也是组装器唯一消费内容；组装后不携带作者、UUID 或引用元数据。
- `开场文本`：使用对应条目的字符串 `entry.data`，独立于 `stat_data`。
- `system.当前剧本`：组装时设置为开场白 `key`。
- 空集合引用合法，组装为空对象。

最终 `stat_data` 必须通过工坊结构预检，并由当前角色卡注册的 MVU schema 作为宿主运行时最终契约。

## 失败语义

组装是全有或全无操作。以下情况返回结构化错误，不输出部分结果，也不触发宿主写入：

- 开场白不存在或 `可用: false`。
- UUID 悬空或同一资源被重复引用。
- 普通集合或种族出现重复运行时 `key`。
- 角色 `type` 未知、缺少 `user` 或同一剧本引用多个 `user`。
- 组装结果不符合运行时结构预检。

错误包含分类、相关 UUID 和可读说明。UI 只展示错误，不补全或跳过错误资源。

## 宿主应用边界

- 等待 MVU 初始化后，将组装结果写入最新消息楼层的 `stat_data`。
- 将同一楼层正文替换为开场文本。
- 写变量成功但消息替换失败时，必须尝试恢复原 MVU 数据；恢复失败必须显式报告。
- 宿主应用属于尘史模块的开局流程。创意工坊只维护并持久化资产，不提供“应用到当前聊天”。
- 创意工坊导出的是版本化开发资产包，不将 `{ scenario, stat_data, opening_text }` 运行态数据称为剧本包。

旧式从单个世界书条目解析完整 `<VariableInsert>` 的剧本加载职责已被本契约取代。

## 格式边界

- 只接受当前完整嵌套地图格式；地图条目必须包含 `data`，不接受旧 `root` 拓扑。
- 世界书出现 `<地图节点>配置` 时明确加载失败，不做运行时迁移或猜测。
- `<地图>配置` 必须且只能包含一张地图。
