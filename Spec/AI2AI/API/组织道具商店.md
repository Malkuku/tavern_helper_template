# 组织道具商店

道具货架刷新在生成结果通过校验并成功写回后显示一条顶部“道具商店刷新成功”通知；点击进入道具商店。仅触发生成、取消或失败均不提示。

刷新和交易均通过 `MvuUtil.updateMvuDataByObjWithPatch`
把实际变量差分追加到当前正文后保存变量并读回核对。差分包括货架增删、随身库存、积分；正文从上一楼重算时可按顺序恢复，原有正文和结果标签保留。刷新本身不追加剧情行动日志；交易日志与差分一并保存，写入失败时撤回本次正文追加。

## 数据契约

`stat_data.商店`、`角色.user.物品` 与顶层 `仓库` 均以道具名为键，值包含
`图标`（可选的安全完整 SVG）、`描述`、`作用`、`评级`、`价格`、`数量`、`耐久`。新生成的货架商品若缺少可用 SVG，界面以默认图形回退。`评级`
只取 N/D/C/B/A/S，表示道具自身的强度与品质，不限制玩家使用。N 级可通过开局校验、生成解析、购买、库存转移与丢弃，不受生成评级上限过滤；玩家、技能和任务评级仍为 D/C/B/A/S。`价格`
是单件基准价值，单位为恶堕积分，与取得成本无关；`耐久` 是当前值，不保存最大耐久。一次性消耗品可用耐久 1 表示。不保存
`类型/类别`。

同名道具视为同一规格，描述、作用和评级保持一致；图标以已有对象为准。不同规格需使用不同名称。价格不参与规格判定，数量与当前耐久可以不同。存取或购买时若目标已存在，保留目标价格元数据，同名合并数量，耐久按
`(目标耐久×目标数量 + 来源耐久×本次数量) / 合并后数量`
加权并向上取整。反复存取可能因取整增加少量耐久，这是已接受的规则。无旧存档迁移要求。

## 手动刷新

新开局由唯一开局固定数据提供 3 件初始货架道具，可直接购买；初始上架不消耗手动刷新次数。玩家手动刷新成功后仍以生成结果替换整张货架。

手机“道具商店”的按钮发出 `Chat_On_ItemShop`；该事件对应的生成规则为
`生成商店道具.ini`。宿主侧绑定状态不由本仓库判断，实际生成时序在酒馆中验证。规则读取玩家当前评级、随身道具、仓库道具和旧货架的道具摘要，不注入 SVG 原文。生成结果用单个
`<shopVariable>{...}</shopVariable>`
包裹，生成目标为 6 个不同名称的商品；实际返回数量偏离目标时仍逐项校验，只上架有效商品。全无可用项时保留原货架且不结算；每项库存量由 AI 决定，高评级商品应更稀少。玩家当前评级的后一档为硬上限，低级商品可出现；脚本逐项丢弃超限商品。

单件价格建议区间：D 2～4、C 7～12、B 22～35、A 70～110、S
220～330 积分。AI 根据用途、效果和初始耐久在区间附近确定价格；区间只指导生成，不作为脚本硬校验。价格 0 表示免费道具，可上架和购买；负价无效。手机读取本次最新的完整结果标签，忽略生成项的多余字段；必要字段、数量和金额逐项校验，无效商品不写入也不展示。不安全或非正方形的图标不写入变量，使用默认图形。同名时脚本沿用已有规格及 SVG，但保留本次解析出的价格，不被随身、仓库或旧货架价格覆盖；已有多个来源的同名规格互相冲突时跳过该商品，不影响其他商品。

生成结果可以写回触发时的同一消息楼层，也可以进入后续楼层；手机从触发楼层扫描到当前楼层，与触发前的结果标签比较，只结算本次新增或变更的 user 或 assistant 楼层结果，系统楼层不参与；失败标签清理同样支持 user 和 assistant 楼层。生成结束事件的楼层号仅用于通知，手机同时观察酒馆发送按钮从忙碌恢复，并在正文写入事件后重新检查；等待期间还会持续读取本次正文，覆盖宿主未发出写入事件的情况。未找到标签时继续等待，不按固定秒数误报无结果。等待期间可通过手机“取消生成”停止酒馆生成；酒馆停止生成事件也会立即取消当前刷新等待，取消后忽略排队及迟到结果，不扣费、不计次，并清除本次定向请求（如有）。

普通刷新每次固定 2 点恶堕积分，无首次免费、次数递增或周重置，不限制刷新次数。定向刷新另收现有按评级计算的附加费。`商店下次刷新时间`
和 `商店主动刷新次数`
仅为旧存档和开局协议兼容字段，不再参与计价或更新。至少有一件可用商品时，在一次变量写入中替换整张货架并扣费；部分有效仍按一次刷新结算。跨周保留货架。全无可用项、积分不足、用户取消或聊天切换不扣费、不改货架；取消后忽略迟到结果。

玩家可输入希望出现的道具用途或效果，选择定向刷新。本次报价为普通刷新价加按玩家累计评级贡献计算的评级附加费：D 5、C 10、B
15、A 20、S
25 点。手机在触发事件前将请求 ID、类型、要求与普通报价写入`手机.定向刷新`；`生成商店道具.ini`仅读取类型为道具的本次要求，将其作为提高相关结果出现机会的参考，不保证指定内容必出。成功上架时重新核对请求与报价，在同一次变量写入中扣总价、更新货架与次数、清除请求。失败或取消不扣费并清除请求；脚本重载后发现无活动生成的遗留请求时清除。普通刷新会先清除遗留请求，避免沿用旧偏好。

界面勾选“定向刷新”后展开偏好输入，原“刷新货架”按钮直接显示普通报价加当前评级附加费并提交定向请求；未勾选时该按钮提交普通刷新。勾选但未填写偏好时不能提交。

手机在消息接收、消息更新及 MVU 更新完成后检查本次结果。全无可用项或写入失败时自动清理本楼失败的道具标签，暂时失败则后台重试；清理不阻断后续刷新，不要求玩家手动操作。清理只删除所定位的标签，不改动同楼其他内容。

## 交易与使用

成功购买或丢弃时在当前楼层正文追加一条
`<systemLog>`，记录道具名称和数量；购买记录实际积分消耗，丢弃记录来自随身物品或仓库。失败时不保留本次记录。

购买指定正整数数量，结算
`货架单件价格×数量`，从货架扣库存并加入随身。同名持有物按上述规则合并；货架剩余数量为零时删除条目。道具出售取消，改为丢弃：可选择随身或仓库作为来源，经确认后只从所选位置扣除正整数数量，归零时删除条目，不返还积分，也不依赖价格字段。购买、丢弃和库存转移都通过手机 Store 的串行队列读取最新楼层变量，并一次性写回；无效数量、规格冲突或购买余额不足时拒绝写入。

随身道具的“使用道具”入口只把名称、使用数量、作用及当前耐久组成待发送文本放入酒馆聊天输入框，保留原有未发送内容，不自动发送，也不在点击时扣数量或耐久。实际使用结果由后续剧情和变量更新处理。变量卷轴也提供随身道具快捷使用入口，沿用同一段使用意图字段；见[变量卷轴快捷使用](./变量卷轴快捷使用.md)。

道具货架、丢弃列表、随身库存和变量卷轴复用
`OwnedAssetCard`，展示评级、数量和耐久，按现有评级配色区分 N 暗灰、D 灰、C 绿、B 蓝、A 金、S 粉紫，并沿用 A/S 光效。价格字段保留：商店购买区显示货架单价，购买按钮显示随所选数量变化的总价；随身、仓库、丢弃列表及变量卷轴不展示持有道具价格。刷新费用仍正常展示。技能价格与出售规则不受此调整影响。
