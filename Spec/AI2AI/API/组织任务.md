# 组织任务

## 数据契约

首位目标选择时，手机直接向已接任务表发放一项 D 级 `初始接触：<角色key>`，奖励 5 点恶堕积分，用于以伪造身份与所选目标建立首次联系；不占用每日任务刷新次数。

魔法少女手机使用顶层 `stat_data.任务候选` 存未接取候选，`stat_data.任务` 存已接任务，均以唯一任务名为键。任务项字段为 `描述`、`目标`、`当前进度`、`评级`（D/C/B/A/S，任务自身难度）、`奖励`（正整数，单位为恶堕积分）与 `已完成`（布尔值）；不保存过期时间。生成候选的 `当前进度` 为 `未接取`、`已完成=false`。接取时移入已接任务并把进度设为 `进行中`。后续独立规则负责根据剧情更新已接任务的进度与 `已完成`；本轮不实现自动完成判定。

`系统.任务下次刷新时间` 是下一世界日 00:00；`系统.任务主动刷新次数` 记录本世界日成功刷新次数 0 或 1，不再触发 EJS 自动生成。新开局组装时，根据开局世界时间初始化 `任务统计.开始周` 和空白本周统计；没有首周豁免或折算。

`任务统计` 只保存 `开始周`、`本周`和`上周`。每份周统计记录周一日期、领奖完成数、放弃数，以及两类各自的 D/C/B/A/S 分布。统计按世界时间周一 00:00 归周，更早的汇总不保留；当周没有任务操作时，界面和问责规则将缺失的周汇总视为 0。

## 刷新与接取

手机“组织任务”按钮发出 `Chat_On_Quest`，对应 `生成任务.ini`。宿主侧事件绑定与实际生成时序须在酒馆联调。规则读取当前正式地图节点、周边节点及最近消息提到的节点，并从其他正式叶子节点随机抽取预览；只提供地点路径、描述及聚焦节点详情，不把随机地点当作玩家位置。规则还读取 `系统.已发现目标` 中能精确匹配现有主要/次要角色的 key 和简要角色信息，优先以已发现目标推进主线；有已发现的主要角色时，候选中至少包含一项可能增进好感度的援助或合作任务，实际好感度变化由剧情与变量规则决定。没有已发现目标时可安排线索调查，但不得假定玩家已指定攻略对象。六项候选保持行动和情绪方向多样，仍要求至少 2 项恶堕、色情或调教倾向任务；涉及性内容时只使用已确认成年的角色并以双方同意为前提。

规则输出单个 `<questVariable>{...}</questVariable>`，恰好 6 个不同名称的候选任务，且不得与已接任务重名。奖励生成参考区间为 D 5～10、C 12～24、B 28～50、A 60～100、S 120～180 恶堕积分；区间仅指导生成，脚本只校验正整数和完整字段。至少 2 项适合玩家当前评级。

每天最多成功刷新一次，不提供付费刷新。生成结果校验成功后，一次性替换剩余候选并更新每日刷新字段；已接任务保留。未刷新时旧候选仍可接取。无效生成、用户取消或聊天切换不消耗机会、不部分写入，取消后迟到结果忽略。

同时最多 4 项已接任务，已完成但未领奖仍占名额。接取时从候选移到已接；主动放弃未完成任务时删除，并计入当前周放弃统计，不回候选。已完成任务不能放弃，只能领奖。

手机成功接取或放弃任务时，在当前楼层正文各追加一条 `<systemLog>`，记录任务名称和行动；校验失败或写入失败不保留本次记录。

## 领奖与周指标

任务 `已完成=true` 后才可领取。领取在手机 Store 串行写入队列中重新读取最新楼层变量，校验任务和积分，一次性增加恶堕积分、删除任务、更新当周完成数与评级分布；同一任务不能重复领取。KPI 按**领取奖励时所在的世界周**计数，每项计 1，不按评级加权。跨周领取计入领取当周。

领奖成功时在当前楼层正文追加一条 `<systemLog>`，记录任务名称和实际获得的恶堕积分。

面向玩家的目标表述为每世界周完成至少 7 项任务；完成后领取奖励才计入 KPI。7 项是达标线，达标后仍可继续完成并领取。`任务周指标.ini` 常驻向 AI 提供本周已计入数、剩余数及未达标可能面临组织惩罚的提醒；上周未达标时另提供组织问责剧情指导。规则不直接扣资源或修改状态；同一未达标周的问责不要重复演出，不保存额外的“已问责”标记。
