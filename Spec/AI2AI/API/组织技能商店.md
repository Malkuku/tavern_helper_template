# 组织技能商店

## 数据

`stat_data.技能商店` 以技能名为键，单项包含`图标`、`描述`、`战力评级贡献`、`作用`、`价格`、`适用评级`。`角色.user.技能`使用同一字段结构，但`价格`是累计投入：新购为售价，同名升级后加上升级售价。初始赠送技能价格为 0。技能只保存当前完整效果，不保留等级表或历史版本。

`角色.user.当前评级` 由全部持有技能的`战力评级贡献`求和决定。总分门槛高于`生成技能.ini`中的单项技能等级参考：D 0～39、C 40～179、B 180～999、A 1000～2999、S 3000 及以上。0 分保持初始 D 级。技能购买、同名升级、出售与叙事直接修改技能表后均重新计算；商店货架刷新不影响评级。评级写入与购买、出售交易在同一次变量写入中完成。

沿用`系统.技能下次刷新时间`和`系统.技能主动刷新次数`。前者是手机脚本计价的周界标记，后者记录当前计价周成功刷新的次数；两者不用于触发 AI。世界时间达到下次周一时，脚本按次数 0 报价；下一次成功刷新时更新两个字段。商店货架跨周保留。

## 手动刷新

独立手机 APP 的刷新按钮发出 `Chat_On_SkillShop`，该事件对应的生成规则为`生成技能.ini`。宿主侧绑定状态不由本仓库判断，实际生成时序在酒馆中验证。规则输出一份`<skillVariable>{...}</skillVariable>`，恰好 6 个不同名称的技能。玩家有技能时，AI 自选 1～3 个已有名称生成完整升级版，其余为新技能；持有技能不足 3 个时以上限为持有数量，没有持有技能时全为新技能。同名候选须保留原有能力并提高`战力评级贡献`。

手机脚本只在本次按钮触发的生成期间读取 assistant 正文结果，校验字段、安全 SVG、正方形 viewBox、数量、同名范围和贡献递增。校验成功后在一次变量写入中替换整个货架、扣积分、更新下次周一时间和次数，并结束本次生成状态。串行队列中的后续重复事件会跳过；失败不部分写入，不扣费，可以再次点击刷新。没有持久待刷新请求；脚本重载会取消尚未完成的刷新，玩家可重新点击。
等待生成期间可手动取消；取消后忽略迟到结果，不扣费。

本周刷新报价按已成功次数依次为 0、20、40、80、80……恶堕积分，单次封顶 80；每周一 00:00 按世界时间重置报价。积分不足时不能刷新，不限制每周刷新次数。

## 交易

购买时从最新变量中再次检查货架、余额和升级贡献。新购把商店技能复制到玩家技能；同名升级覆盖完整版本，并把原累计价格与本次售价相加。购买后移除货架项。同名但贡献未提高时拒绝购买。

出售从玩家技能中删除该技能，返还`floor(累计价格 / 2)`积分；确认前展示实际返还值。初始赠送技能累计价格为 0，出售返还 0。

购买、出售和刷新结算均使用手机 Store 的串行写入队列；聊天切换时放弃过期写入。真实生成时序需在酒馆中验证。
