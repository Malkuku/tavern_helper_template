# 微信正文增量与手机交互

## 数据来源

`src/手机界面/types.ts` 中 `stat_data.手机.微信` 是账号、好友、会话、消息和 `准备发送` 的权威数据。微信页面只展示当前聊天楼层的变量，通讯录从 `账号.user.好友` 派生，会话列表只展示成员包含 `user` 的会话。新私聊使用 `私聊:user&<账号ID>`；首次发送后由正文增量创建会话。

## 发送流程

用户发送文字、引用回复或已有表情包时，Store 将 `{ 会话, 时间, 内容 }` 写入 `准备发送`，随后触发 `Chat_On_WeChat`。时间读取 `世界.时间`。在正文确认前不向会话追加消息；待发送内容保留，可重试事件。未初始化、无有效世界时间、目标不是好友或已有待发送时，发送报错。

## 正文协议

主动和后台规则在 assistant 正文中输出 `<WeChatLog>{...}</WeChatLog>`。JSON 至少包含 `新增消息`、`好友事件` 数组；主动发送成功时可含 `清空准备发送: true`。新会话须附 `会话信息`。Store 在消息接收、更新和生成完成后检测当前 assistant 楼层，解析全部日志并作为一次操作应用；校验失败不写入部分数据，也不清空待发送。

带 `清空准备发送` 的日志，其第一条新增消息必须与当前 `准备发送` 的会话、时间和内容完全一致，发送者为 `user`。按聊天变量 `magicGirlWeChatAppliedLogs` 记录楼层日志签名，重复宿主事件不重复追加。聊天切换后，过期任务不得写入新聊天。手机未打开时，只要手机脚本运行，Store 仍监听正文事件。

## 界面范围

微信提供会话列表、聊天详情、通讯录、好友申请与个人账号。普通文字、语音、表情包、红包、转账、引用及转发使用各自展示样式；群聊显示成员。发现页没有对应变量数据时显示空状态。好友申请和处理直接改写请求及双方好友数组。
