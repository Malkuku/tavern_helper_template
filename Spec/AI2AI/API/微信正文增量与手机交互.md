# 微信正文增量与手机交互

聊天详情为独立页面，展示成员、聊天记录查找、免打扰和置顶状态；详情中的“+”在私聊发起群聊、在群聊邀请好友。建群从 user 的好友中多选，创建与邀请在一次变量更新中完成。会话显示昵称、图片、免打扰和置顶保存在手机脚本变量 `magicGirlWeChatAppearance`，按会话 key 区分，只改变界面展示，不改写 `stat_data.手机.微信` 的会话、账号或消息。详情页不显示聊天背景、清空聊天记录和投诉入口。

## 数据与会话

`stat_data.手机.微信` 是微信权威数据，类型见 `src/手机界面/types.ts`。账号保存当前好友关系；`会话.消息[]` 按顺序保存普通消息与操作。每个会话的消息与操作共用从 1 开始连续递增的 `楼层ID`，数组第 n 项的 ID 为 n。旧变量中的消息按数组位置补齐。私聊 key 是 `私聊:<账号A>&<账号B>`，包含 user 时 user 在前；两个 NPC 的账号顺序均可。界面主动创建 NPC 私聊时使用稳定排序。群聊 key 由创建事件提供且必须唯一；展示名称可重名。微信界面只列出成员包含 user 的会话，通讯录由 `账号.user.好友` 派生。

好友申请、通过、拒绝、拍一拍、创建群聊、邀请进群都作为操作项进入消息流。申请会创建私聊；待处理状态从该私聊最近一轮申请及处理操作推导，拒绝后可再次申请。新群先只有创建者，后续按顺序邀请好友。非好友不能发送普通私聊消息；群成员只能邀请自己的好友。正文与界面共用写入前校验。

## 发送与正文协议

玩家点击聊天输入栏的“添加”时，Store 将内容按顺序写入或追加到同一会话的 `准备发送.内容[]`，此时 `已确认=false`，不触发生成。界面显示待发送行和“确认发送给对方”；玩家可继续添加或清空。显式确认时将 `已确认=true` 并触发一次 `Chat_On_WeChat`。确认后到正文回写前不再允许追加，只能等待或重试生成。旧缓冲缺少 `已确认` 时按已确认处理。不同会话的待发送内容不合并。引用仍是本批消息的顶层快照，只能随首项加入；后续试图添加引用时明确报错。时间取首次添加时的 `世界.时间`。正文确认前不向会话追加消息；待发送内容保留，可重试。未初始化、无有效世界时间或不符合好友关系时明确报错。

主动和后台规则在 assistant 正文中输出 `<WeChatLog>{"事件":[...]}</WeChatLog>`。事件数组按发生顺序原子应用，事件类型为 `消息` 或 `操作`。由第一条普通消息创建新私聊时提供 `会话信息`；好友申请操作可直接创建私聊。创建群聊事件必须提供唯一会话 key、创建者与展示名称，同一日志后续事件可沿用。消息 `内容[]` 可含文字、语音、表情包、红包、转账、名片字符串标签及转发对象；引用保存原消息 `楼层ID` 和显示快照；每个正文事件带所属会话的 `楼层ID`。

领取红包、收款、退回转账会追加操作项，供会话展示行为提示，同时更新原消息的 `特殊内容状态[内容下标]` 供卡片展示。款项操作通过 `{ 楼层ID, 内容下标 }` 精确定位原消息中的卡片。当前没有金额结算契约，这些动作不修改角色金钱。第一版不支持撤回或退群。

Store 在消息接收、更新和生成完成后检测当前 assistant 楼层，解析全部日志并一次应用；校验失败不写入部分数据，也不清空待发送，并在微信页面显示失败原因。首条新增事件若与待发送的楼层 ID、会话、user、内容和可选引用一致，且正文时间不早于待发送时间，就确认发送并清空缓冲。待发送时间取发送时的世界时间，正文聊天时间可以向后推进，不要求世界时间同步变化；确认后保存正文中的实际时间。年月日允许不补零，比较时规范化；时间格式无效或早于待发送时间仍报冲突。同步按会话楼层 ID 对照当前微信变量：同 ID 同内容跳过，同 ID 异内容报冲突，新 ID 必须紧接会话末尾；不再使用聊天变量日志签名。聊天切换后的过期任务不能写入新聊天。手机未打开时，只要手机脚本运行，Store 仍监听正文事件。

连续发送时，旧日志按会话楼层 ID 跳过，只用新 user 事件确认本次待发送。历史无 ID 日志仅在其事件已按顺序存在于当前微信变量中时跳过；无 ID 且未入库的事件要求按新规则重新生成。

## 界面

同步失败时，微信页面只清除定位到的出错 WeChatLog 标签，保留同楼其他日志和正文；未闭合标签无法定位时明确报错。消息长按菜单可删除所选会话该楼层及其后续消息；删除时同步移除正文中相应的 WeChatLog 事件及微信变量中的消息，避免再次同步。NPC 私聊 key 接受双方账号 ID 的任一排列；转发选择聊天使用居中的悬浮面板，长按菜单不阻断背景交互。

连续发送确认：普通文字、语音、表情包、转账、名片、名片附言和转发先进入当前会话的待发送列表；只有玩家点击确认按钮才触发正文生成。待发送的每个 `内容[]` 项仍显示为独立消息行。确认失败时保留缓冲并提供重试；正文确认后清空缓冲。

2026-09-26 截图参考更新：聊天扩展面板只提供转账和名片发送，红包发送入口移除；历史红包仍可读取和领取。长按消息弹出仅含“转发”“引用”的菜单；引用预览显示在新消息气泡下方。名片卡片展示账号头像、昵称及“个人名片”。转账使用独立金额输入界面，金额以元显示，新发送的金额标签只保存数字；历史金额末尾的 `g` 在界面展示时去除。转账消息卡片为橙色，直接作为消息行卡片展示，不再嵌在普通气泡里。名片和转发使用可搜索的联系人或聊天列表，选中后显示发送确认层。

名片发送确认层允许填写可选附言；一次发送的 `内容[]` 先放名片标签，再放附言文字，界面按顺序显示为两条独立消息行。转账和名片在内容已进入待发送缓冲或已被正文确认后退出确认层；发送前校验失败时保留输入并在当前界面显示错误。收款结果写入后关闭款项详情。确认层的阴影只覆盖确认卡片周边，不使用跨越整个视口的阴影。

微信提供会话、聊天、通讯录、好友申请和个人账号页面。普通文字、语音、表情包、历史红包、转账、名片、引用、转发与消息流操作有各自展示；群聊显示成员。同一消息的 `内容[]` 各项按顺序显示为独立消息行，每项各有头像和气泡；例如两个文字项显示为连续两条消息。引用附在首项消息的气泡下方；长按菜单中的引用和转发针对被点击的单个内容项。聊天扩展面板可发送转账、名片；语音入口可填写转写内容和时长。历史红包和转账卡片可打开详情，收取者可领取红包、收款或退回转账，同一款项只能处理一次。点击对方头像可拍一拍；群聊详情可邀请好友。名片可打开账号资料并发起聊天或申请。发现页展示截图中的入口。

四个主标签使用用户提供的微信截图作为布局基线。手机脚本作用域的 `darkMode` 布尔变量控制明暗主题，通过 `getVariables({ type: 'script', script_id: getScriptId() })` 读取；未设置时为白天模式。无数据契约的入口点击后显示“暂未开放”。聊天详情显示头像、左右气泡、时间分隔、输入栏与表情或扩展面板；待发送且宿主正在生成时显示输入动画。手机应用界面提供 Home 按钮返回桌面。

表情包初始为空。用户选择本地图片并命名后，图片写入当前楼层 `手机.微信.账号.user.表情包[名称]`；重复名称或无效图片不写入。脚本变量 `magicGirlWeChatStickerSnapshot` 保存 user 上传的表情包备份；上传需等待备份成功再报告完成。读取楼层变量时恢复缺失的备份图片，且备份不覆盖楼层中同名的现有表情。
