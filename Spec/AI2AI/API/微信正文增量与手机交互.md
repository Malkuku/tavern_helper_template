# 微信正文增量与手机交互

## 数据来源

`src/手机界面/types.ts` 中 `stat_data.手机.微信` 是账号、好友、会话、消息和 `准备发送` 的权威数据。微信页面只展示当前聊天楼层的变量，通讯录从 `账号.user.好友` 派生，会话列表只展示成员包含 `user` 的会话。新私聊使用 `私聊:user&<账号ID>`；首次发送后由正文增量创建会话。

## 发送流程

用户发送文字、引用回复或已有表情包时，Store 将 `{ 会话, 时间, 内容 }` 写入 `准备发送`，随后触发 `Chat_On_WeChat`。时间读取 `世界.时间`。在正文确认前不向会话追加消息；待发送内容保留，可重试事件。未初始化、无有效世界时间、目标不是好友或已有待发送时，发送报错。

## 正文协议

主动和后台规则在 assistant 正文中输出 `<WeChatLog>{...}</WeChatLog>`。JSON 至少包含 `新增消息` 数组；主动发送成功时可含 `清空准备发送: true`。新会话须附 `会话信息`。Store 在消息接收、更新和生成完成后检测当前 assistant 楼层，解析全部日志并作为一次操作应用；校验失败不写入部分数据，也不清空待发送。
`好友事件` 在没有好友变更时可以省略，解析为 `[]`。解析或应用失败时，微信页面显示同步失败原因。

日志的第一条新增消息若与当前 `准备发送` 的会话、发送者 `user`、时间和内容完全一致，就表示发送已确认，应用日志后清空待发送；显式写 `清空准备发送: true` 时必须满足同样的匹配条件。已应用日志重复触发时只补清残留的匹配待发送，不重复追加消息。按聊天变量 `magicGirlWeChatAppliedLogs` 记录楼层日志签名。聊天切换后，过期任务不得写入新聊天。手机未打开时，只要手机脚本运行，Store 仍监听正文事件。

## 界面范围

微信提供会话列表、聊天详情、通讯录、好友申请与个人账号。普通文字、语音、表情包、红包、转账、引用及转发使用各自展示样式；群聊显示成员。发现页展示截图中的功能入口。好友申请和处理直接改写请求及双方好友数组。

四个主标签使用用户提供的微信截图作为布局基线。手机脚本作用域的 `darkMode` 布尔变量控制微信明暗主题，读取方式与尘史使徒界面相同：`getVariables({ type: 'script', script_id: getScriptId() })`；未设置时为白天模式。发现页及其他暂无数据契约的可见入口点击后只显示“暂未开放”提示；通讯录的添加朋友、好友申请、会话与聊天仍执行已有真实逻辑。
聊天详情参照用户提供的截图显示头像、左右气泡、时间分隔、输入栏与表情/扩展面板；待发送且宿主正在生成时显示“对方正在输入中...”动画。手机应用界面提供可见的 Home 按钮返回桌面。
表情包初始为空；用户从聊天面板选择本地图片并命名后，图片数据写入当前消息楼层的 `手机.微信.账号.user.表情包[名称]`，可直接预览和发送。重复名称或无效图片不写入。Home 位于手机状态栏，避免遮挡微信底部操作区。
当前手机脚本变量 `magicGirlWeChatStickerSnapshot` 备份 `user` 上传的表情包图片。上传完成后需等待脚本备份写入再报告成功；读取微信楼层变量时，已有楼层表情补入脚本备份，备份中存在而楼层缺失的表情恢复到当前楼层。备份不会覆盖楼层中同名的现有表情。这样删除含上传记录的楼层后，仍能从脚本变量恢复图片。
