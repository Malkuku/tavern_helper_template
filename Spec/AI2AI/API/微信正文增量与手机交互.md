# 微信正文增量与手机交互

玩家可见聊天应用名称为 **Weline**。本文中的“微信”指保留的内部数据、变量和日志协议名称；视觉与导航以
[Weline 聊天应用设计](../Weline聊天应用设计.md) 为准。

聊天详情为独立页面，展示成员、聊天记录查找、免打扰和置顶状态；详情中的“+”在私聊发起群聊、在群聊邀请好友。建群从 user 的好友中多选，创建与邀请在一次变量更新中完成。会话显示昵称、图片、免打扰和置顶保存在手机脚本变量
`magicGirlWeChatAppearance`，按会话 key 区分，只改变界面展示，不改写 `stat_data.手机.微信`
的会话、账号或消息。详情页不显示聊天背景、清空聊天记录和投诉入口。

## 数据与会话

`stat_data.手机.微信` 是微信权威数据，类型见 `src/手机界面/types.ts`。账号保存当前好友关系；`会话.消息[]`
按顺序保存普通消息与操作。每个会话的消息与操作共用从 1 开始连续递增的
`楼层ID`，数组第 n 项的 ID 为 n。旧变量中的消息按数组位置补齐。私聊 key 是
`私聊:<账号A>&<账号B>`，包含 user 时 user 在前；两个 NPC 的账号顺序均可。界面主动创建 NPC 私聊时使用稳定排序。群聊 key 由创建事件提供且必须唯一；展示名称可重名。微信界面只列出成员包含 user 的会话，通讯录由
`账号.user.好友` 派生。

微信直接读取 `stat_data.手机.微信`
中的账号和联系人；会话列表展示 user 所在的群聊与已建立双向好友关系的私聊。“附近的人”按在场、正文检索词和区域检索词筛选。`系统.已发现目标`
只控制目标资料等 App 的展示，不参与微信联系人、好友申请、会话、未读和消息提示的判断。加微信好友也不代表发现对方的魔法少女身份。

好友申请、通过、拒绝、拍一拍、创建群聊、邀请进群都作为操作项进入消息流。申请会创建私聊；待处理状态从该私聊最近一轮申请及处理操作推导，拒绝后可再次申请。新群先只有创建者，后续按顺序邀请好友。非好友不能发送普通私聊消息；群成员只能邀请自己的好友。正文与界面共用写入前校验。

## 发送与正文协议

玩家点击聊天输入栏的“添加”时，Store 将内容按顺序写入或追加到同一会话的 `准备发送.内容[]`，此时
`已确认=false`，不触发生成。界面显示待发送行和“确认发送给对方”；玩家可继续添加或清空。显式确认时将 `已确认=true`
并触发一次 `Chat_On_WeChat`。确认后到正文回写前不再允许追加，只能等待或重试生成。旧缓冲缺少 `已确认`
时按已确认处理。不同会话的待发送内容不合并。引用仍是本批消息的顶层快照，只能随首项加入；后续试图添加引用时明确报错。时间取首次添加时的
`世界.时间`。正文确认前不向会话追加消息；待发送内容保留，可重试。未初始化、无有效世界时间或不符合好友关系时明确报错。

当前会话有未确认的待发送内容且输入框为空时，输入栏不显示重复的“发送”按钮；玩家点击待发送行的“确认发送给对方”完成确认，在空输入框按回车也执行相同确认。输入框有文字时仍将文字添加到待发送内容，扩展功能入口继续可用。没有待发送内容时，空输入不会触发发送。

主动和后台规则在 assistant 正文中输出 `<WeChatLog>{"事件":[...]}</WeChatLog>`。事件数组按发生顺序原子应用，事件类型为
`消息` 或 `操作`。由第一条普通消息创建新私聊时提供
`会话信息`；好友申请操作可直接创建私聊。创建群聊事件必须提供唯一会话 key、创建者与展示名称，同一日志后续事件可沿用。消息
`内容[]` 可含文字、语音、表情包、红包、转账、名片字符串标签及转发对象；历史消息中的 `[捂脸]`
等方括号文本按普通文字显示。引用保存原消息 `楼层ID` 和显示快照；每个正文事件带所属会话的 `楼层ID`。

位置分享是 `内容[]` 中的字符串标签 `<位置 key="地图节点key">`，key 必须逐字等于当前 `stat_data.地图`
某个节点的键，不能用 `世界.地点`
或显示别名代替。双引号与反斜杠遵循 JSON 字符串转义。聊天位置消息显示为可点击的地点卡片；分享位置复用地图导航与搜索，但选点时只显示地点名、进入内部地图入口和“加入待发送”，完整描述与详情留在独立地图 App。后台和主动聊天规则从用户提供的
`地图节点.ini`
上下文识别可用 key，自身不再注入地图 key 列表；新消息若含不存在的 key，整次微信日志写入失败并展示原因。历史卡片所指 key 在当前地图已失效时，点击卡片显示错误，不误跳转。玩家可通过微信“位置”入口在地图组件中选择当前节点的 key 加入待发送；点击收到的位置卡片会打开手机地图并选中对应节点，不更改角色位置。

群聊转账必须先选择一位其他群成员，内容使用 `<转账 金额="数字" 收款人="账号ID">备注</转账>`
保存收款人；私聊继续从会话双方推定收款人，旧私聊转账标签保持可读。新群聊转账若未指定收款人、收款人不是该群成员或指向发送者，发送与正文增量均报错。群聊中仅指定收款人可以收款或退回；历史无收款人的群聊转账显示“未指定收款人”，不可领取或退回，不擅自指定对象。领取红包、收款、退回转账会追加操作项，供会话展示行为提示，同时更新原消息的
`特殊内容状态[内容下标]` 供卡片展示。款项操作通过 `{ 楼层ID, 内容下标 }` 精确定位原消息中的卡片。钱包余额以
`stat_data.角色.user.金钱`
为唯一来源。user 发送转账或红包的消息经正文确认入库时扣款；user 领取其他账号的转账或红包时入账；user 发出的转账被退回时退款。结算与对应微信消息或操作在一次变量写入中完成；重复日志不重复结算，金额无效或余额不足时整次写入失败。金额最多两位小数。第一版不支持撤回或退群。

Store 在消息接收、更新和生成完成后检测当前 assistant 楼层，解析全部日志并一次应用；校验失败不写入部分数据，也不清空待发送，并在微信页面显示失败原因。首条新增事件若与待发送的楼层 ID、会话、user、内容和可选引用一致，且正文时间不早于待发送时间，就确认发送并清空缓冲。待发送时间取发送时的世界时间；确认后保存正文中的实际时间。新增正文事件的最晚时间若晚于当前
`世界.时间`，同次写入将世界时间推进到该时间；较早时间和已入库旧日志不使世界时间倒退或重复推进。事件时间格式或日期无效时整次写入失败。年月日允许不补零，比较时规范化；主动消息正文时间早于待发送时间仍报冲突。同步按会话楼层 ID 对照当前微信变量：同 ID 同内容跳过，同 ID 异内容报冲突，新 ID 必须紧接会话末尾；不再使用聊天变量日志签名。聊天切换后的过期任务不能写入新聊天。手机未打开时，只要手机脚本运行，Store 仍监听正文事件。

连续发送时，旧日志按会话楼层 ID 跳过，只用新 user 事件确认本次待发送。历史无 ID 日志仅在其事件已按顺序存在于当前微信变量中时跳过；无 ID 且未入库的事件要求按新规则重新生成。

## 界面

好友申请按会话操作流中的待处理状态展示；收到的待处理申请在手机悬浮入口、桌面微信图标（含文件夹和 Dock）、通讯录“新的朋友”入口及通讯录标签显示红点。申请处理后红点消失。好友申请创建的私聊在双方尚未成为好友时不列入微信会话列表，申请被拒绝后也不显示；通过申请建立双向好友关系后才显示私聊。申请操作不计入普通聊天消息的未读预览，也不触发普通消息弹窗。申请页完整展示验证消息、账号和处理动作。

微信“位置”入口复用手机地图组件，玩家浏览地图并在节点详情点击分享；发送值仍是该节点的真实 key。个人头像和账号管理图片库提供明确的上传入口、用途说明及结果提示。日历按
`stat_data.世界.时间` 显示游戏日期，无有效日期时提示未设置。

手机桌面以 `magicGirlPhoneLayout`
脚本变量保存图标与文件夹位置；每页最多 12 项。触屏横扫桌面切页，长按图标后拖动，贴近网格左右边缘可在拖拽中切页并跨页放置。文件夹缩略图复用真实应用图标。应用、文件夹、控制中心与桌面切换有短时过渡；系统请求减少动态效果时取消动画。

手机内图片文件入口在写入前提供共用裁剪弹层，可拖动、缩放并选原比例、方形、横向或壁纸比例；可取消或保留原文件。角色编辑器头像固定方形裁剪并保持 256 像素输出。Weline 图片库批量上传逐张裁剪，取消某张不影响其余已确认图片。创意工坊头像已有独立聚焦裁剪。手机壁纸通过设置选图，图片上传至酒馆
`/api/files/upload` 文件目录；脚本变量 `magicGirlPhoneWallpaper`
只记录返回的文件路径。重开手机从脚本变量恢复；上传或变量写入失败时保留当前壁纸；恢复默认时将变量置空。支持 PNG、JPEG、WebP、GIF、AVIF。

微信未读以脚本变量 `magicGirlWeChatRead` 保存每个聊天 ID 下各会话最后已读的楼层位置，不写入剧情
`stat_data`。首次启用时以当前会话消息长度为历史基线；打开会话后将该会话标记已读，其他会话保持未读。未读红点显示在手机悬浮入口、桌面微信图标（含文件夹）、微信标签和会话行。新收到的他人普通消息弹出一条微信预览：手机打开时位于手机屏幕上方，关闭时位于宿主页面上方；点击打开手机并进入对应会话，关闭提示不清除未读。当前正在查看的会话直接标记已读。免打扰会话只显示未读红点，不弹出预览；user 消息、操作项、历史加载与日志重放不弹预览。提示由用户点击进入或手动关闭，不自动计时消失。聊天切换清理瞬时提示，已读位置按聊天 ID 隔离。

“我”中的个人信息页可编辑 user 微信昵称和头像，保存到
`stat_data.手机.微信.账号.user`；服务页可进入钱包，钱包显示角色金钱余额。

同步失败时，微信页面只清除定位到的出错 WeChatLog 标签，保留同楼其他日志和正文；未闭合标签无法定位时明确报错。消息长按菜单可删除所选会话该楼层及其后续消息；删除时同步移除正文中相应的 WeChatLog 事件及微信变量中的消息，避免再次同步。NPC 私聊 key 接受双方账号 ID 的任一排列；转发选择聊天使用居中的悬浮面板，长按菜单不阻断背景交互。

连续发送确认：普通文字、语音、表情包、转账、名片、名片附言和转发先进入当前会话的待发送列表；只有玩家点击确认按钮才触发正文生成。待发送的每个
`内容[]` 项仍显示为独立消息行。确认失败时保留缓冲并提供重试；正文确认后清空缓冲。

聊天扩展面板提供位置分享、转账和名片发送，红包发送入口已移除；历史红包仍可读取和领取。长按消息可转发、引用或删除本楼及后续消息；引用预览显示在新消息气泡下方。名片卡片展示账号头像、昵称及“个人名片”。转账使用独立金额输入界面，金额以元显示，新发送的金额标签只保存数字；历史金额末尾的
`g`
在界面展示时去除。转账消息以独立卡片展示，不嵌在普通气泡里；群聊发送页先选收款成员，卡片和详情显示指定收款人。名片和转发使用可搜索的联系人或聊天列表，选中后显示发送确认层。

名片选择范围包括已有 Weline 账号和当前角色名单中的非好友；未建号角色的账号在名片加入待发送时一并创建，好友关系保持为空，收件会话仍须符合原有发送条件。名片发送确认层允许填写可选附言；一次发送的
`内容[]`
先放名片标签，再放附言文字，界面按顺序显示为两条独立消息行。转账和名片在内容已进入待发送缓冲或已被正文确认后退出确认层；发送前校验失败时保留输入并在当前界面显示错误。收款结果写入后关闭款项详情。确认层的阴影只覆盖确认卡片周边，不使用跨越整个视口的阴影。转账金额输入页显示当前零钱余额；金额超过角色金钱时立即显示“余额不足”并禁用加入待发送。提交时再次校验，正文确认入库时仍由 Store 检查余额。

Weline 提供会话、聊天、联系人、好友申请和个人账号页面。普通文字、语音、表情包、历史红包、转账、名片、引用、转发与消息流操作有各自展示；语音消息显示时长与转写内容，不提供没有音频数据支撑的播放控件。群聊显示成员。同一消息的
`内容[]`
各项按顺序显示为独立消息行，每项各有头像；普通文字有气泡，表情包图片直接显示，不带气泡背景、边框或尖角。例如两个文字项显示为连续两条消息。单个文字项也允许普通对话与一个或多个
`<表情包>名称</表情包>` 相连，界面按原顺序拆为独立的文字气泡和表情图片，消息原文与 `内容[]`
下标不改。引用附在首个显示项下方；右键或长按菜单靠近所选消息出现，点空白处可关闭。引用和转发针对被点击显示项所属的原内容项；选中引用后，输入栏上方可取消引用。聊天扩展面板可发送位置、转账、名片；语音入口可填写转写内容和时长。历史红包和转账卡片可打开详情，收取者可领取红包、收款或退回转账，同一款项只能处理一次。点击对方头像可拍一拍；群聊详情可邀请好友。名片可打开账号资料并发起聊天或申请。

主导航为“消息 / 联系人 / 我的”，使用 Weline 自有视觉。手机脚本作用域的 `darkMode` 布尔变量控制明暗主题，通过
`getVariables({ type: 'script', script_id: getScriptId() })`
读取；未设置时为白天模式。旧版仅显示“暂未开放”的仿真栏目不再作为入口。聊天详情显示头像、左右气泡、时间分隔、输入栏与表情或扩展面板；待发送且宿主正在生成时显示输入动画，正文接收失败后立即停止动画、标明失败并保留待发送内容供重试。手机底部 Home 按钮返回桌面。

内置表情图片及 `[名称]`
行内替换已撤销。表情面板只提供玩家自行上传的表情包；所有方括号文本均按普通文字显示，已有聊天消息无需迁移。聊天表情面板提供“管理表情”入口，进入账号管理的表情包页并默认选中 user。共享表情库使用脚本变量
`magicGirlWeChatStickerLibrary`
保存唯一名称到图片引用的映射；引入时从文件、图片库或外部 URL 选图并填写名称，同名不覆盖。账号从库中选用名称，`账号[id].表情包[名称]`
保存 `sticker://名称`，解析时到共享库获取图片；移除账号选用不删除库图片。聊天表情面板读取
`账号.user.表情包`，返回聊天后即可选择新表情加入待发送列表。资料页的昵称、头像与好友关系继续由“保存账号”提交。

自定义表情包初始为空。微信图片库以脚本变量 `magicGirlWeChatImageLibrary` 保存图片 data
URL，上传时按图片内容去重；库内图片使用 `script-image://<图片ID>`。头像继续保存图片 URL，新表情的账号引用使用
`sticker://名称`；旧账号表情中的外部 URL、库内 URL 和 data
URL 作为历史数据继续显示，不再作为新建账号表情的主路径。账号字段始终位于当前楼层
`stat_data.手机.微信.账号`，自定义表情包消息仍以独立的 `<表情包>名称</表情包>`
显示；与文字相连时仍按上一节拆成独立气泡。名称先在发送者账号中查找；找不到或图片引用不可用时依次查找 user 和当前聊天中的其他账号。重名时按此顺序取首个可显示的图片；全都找不到则显示表情包名称。微信脚本变量
`magicGirlWeChatMediaSnapshot` 备份各账号的头像与表情包引用，楼层中缺失的表情可恢复，同名现有表情不被覆盖。旧
`magicGirlWeChatStickerSnapshot` 中的 user 图片在读取时迁入图片库与新备份，随后停止使用旧变量。

新聊天首次从世界书组装时，若脚本媒体备份包含同 ID 账号，应用备份头像与表情包；库内引用缺失则阻止本次初始化并报告错误。已有楼层不因此覆盖现有同名表情或头像。Weline“我的”页的“账号与图片”内提供“账号管理”，进入账号资料时输入固定密码
`987`，离开管理页后需重新输入；从聊天表情面板进入“表情包管理”无需密码，若再切到账号资料则要求密码。管理页可查看并编辑全部内部微信账号；普通聊天、联系人和附近的人也不使用目标发现名单过滤。可编辑昵称、头像、账号选用的表情名称和好友。好友关系在同一次楼层写入中对双方更新。图片库图片可供多个账号复用；手动清理时阻止删除当前聊天账号、脚本媒体备份或共享表情库仍引用的图片。脚本级图片库可能还被其他聊天使用，跨聊天引用无法由当前聊天自动穷举。

账号管理页直接列出当前楼层全部微信账号及尚未建号的主要、次要角色，搜索与选择不受目标发现状态限制。未建号角色只显示建号入口；玩家明确点击后，在当前楼层创建空好友、空表情包的账号，头像沿用该角色的头像规则，不批量自动建号。图片库显示缩略图和完整
`script-image://<图片ID>` 引用，可复制、选为当前账号头像，或在填写名称后引入共享表情库；头像选用后仍需保存账号。脚本变量
`magicGirlWeChatImageCategories`
只保存自定义一级、二级文件夹和图片 ID 的分类归属。旧图片默认未分类；移动图片、文件夹改名或删除均不改变图片内容与引用 URL。删除二级文件夹把图片归到上一级，删除一级文件夹把图片归到未分类；清理图片时同步移除其分类记录。

## 附近的人

手机角色编辑器从当前角色主世界书 `<配置>角色资源`
读取、编辑与新建角色资产，保存只修改主世界书。选择已保存资产“加入”或“替换”时，才完整写入当前楼层的运行态角色；若对应微信账号不存在，同步创建默认账号，头像取角色
`meta.avatar` 或按角色键、样式和主题色生成的稳定默认头像。默认头像提供六款剪影式样式，`auto`
按角色键稳定选取；手机编辑器、角色档案、对话和微信账号使用同一套图形，主题色用于边饰。已有账号保留昵称、表情包及好友资料，头像随明确的加入/替换操作同步。主要角色新建账号与 user 建立双向好友关系；次要角色账号默认不加好友。运行态已有同身份角色必须确认完整替换；角色资源的修改不会静默改动当前剧情。

Weline 联系人页的“附近的人”进入附近角色列表；联系人页和顶栏不提供枚举全部内部账号的添加朋友入口。附近列表读取最近三条聊天消息正文，沿用角色列表 EJS 的在场、名称检索词和区域检索词规则，包含主要角色与次要角色，排除次要角色模板。点选角色时，如该角色 ID 尚无内部微信账号，则以角色名称及随机选取的 32 款无五官 SVG 头像创建账号；已有账号保持原资料。非好友进入账号名片，可填写验证消息并发起好友申请；好友直接打开聊天。
