# 创意工坊资产管理契约

## 责任边界

- 创意工坊只读写当前角色主世界书中的工坊配置条目。
- 资产编辑、资产包安装和删除会修改主世界书；运行时角色加入只修改当前消息楼层 `stat_data`。
- 创建聊天、选择开场白并进入开局属于尘史模块职责。

## 编辑态与可玩态

- 编辑态允许剧本的单例或集合 UUID 引用暂时缺失，但字段类型和资产自身结构必须有效。
- 引用不完整的剧本必须保存为 `可用: false`。
- 可玩态要求剧本标记为可用，显式绑定的地图和角色 UUID 能在对应注册表中解析，初始 `地图索引`
  存在于所选地图，内嵌叙事字段结构有效，并且恰有一个 `user`。
- 完整性是从当前资产集合计算的结果，不持久化冗余状态字段。

## 草稿与保存

- 编辑操作只修改内存草稿。
- 保存前计算资产差异、引用影响和可玩性问题。
- 一次保存涉及的配置条目整体写回；失败时使用本次事务的内存原值恢复。
- 不保留持久化快照、版本历史或成功保存后的撤销点。
- 所有确认弹窗渲染在浮层挂载树内，不能将内容传送回脚本 iframe 文档；放弃草稿、保存审阅、删除、导出和覆盖共享同一可见对话框路径。

## 外部 AI 角色草稿

- 工坊只负责拼装并下载角色提示词，不直接调用 Tavern Helper /
  SillyTavern 的模型 API。用户在外部网页 AI 提交提示词后，将返回的角色 JSON 粘贴回工坊导入。
- AI 往返 JSON 直接采用 `stat_data.角色` 中单个角色对象的结构（角色数据字段与 `meta`），不包含工坊的
  `author/desc/key/type/data` 包装层。当前角色可导出该 JSON 供 AI 修改。
- JSON 导入既可创建角色草稿，也可完整覆盖当前角色的数据字段与
  `meta`；覆盖时保留资产 UUID、类型、key、作者和素材说明，从而维持版本身份与剧本引用。导入不直接写入世界书，仍须经过现有角色编辑、差异审阅和原子保存流程。
- 静态创作规则从当前角色主世界书按条目名读取：角色结构使用 `角色面板说明`、`技能生成标准`、`性格偏移矩阵`；世界观使用
  `八大准则`、灯/铸/刃/冬/心/杯/蛾/启八种术说明和
  `物品参考表`。势力从工坊注册表投影为按业务 key 组织的运行态 JSON，用于约束角色出身、身份和立场；种族按 `type/key`
  投影为运行态 JSON，仅作开放式角色设计参考。两者均不携带 UUID、作者或包装层。地图使用 AI 特供投影：前三层节点保留名称检索词、描述与详情，更深层只保留节点名和层级；所有层级均删除图标、方位与未知附加数据。节日和经济不注入。含 EJS/正文插入协议的
  `次要角色生成` 和暂禁生成的人际关系矩阵不得拼入提示词。
- 不直接复用 `创建user角色任务`、`（配置1）人物编辑任务` 的 MVU 变量更新协议，也不依赖开发机绝对路径。
- 提示词要求外部 AI 返回完整的目标 `stat_data` 角色 JSON。导入按照 Beta `MvuZod.js`
  的角色类型边界检查必填字段、允许字段和基础类型，不用默认模板静默补齐缺失数据。`基础数值` 与 `生命状态`
  不信任 AI 数值，统一根据 `术之等级`
  使用 Beta 同源计算器重算并回满。解析失败、规则缺失或提示词拼装失败时不得创建或修改半成品资产。
- 外部 AI 提示词必须达到零上下文可执行：逐字段说明用途、格式、约束与示例，说明术、技能、特殊状态、物品的设计规则和防八股要求；信息不足时先向用户提问，可多轮澄清，信息充分后才输出 JSON。
- 新建主要/次要角色的 `名称检索词` 与 `区域检索词`模板默认均为 `["$all"]`。`$all`
  是正式运行时通配标签：名称通配使 EJS 无条件加载完整角色，区域通配使 EJS 无条件命中简略角色。AI 可按姓名、别名和称呼完善名称检索词；需要限定区域时只能使用提示词精简地图中的真实节点名。导入时保留 JSON 原值，不由程序覆盖或清洗，方便作者手工编辑。
- 人际关系、性经验和其他明确锁定字段由提示词禁止 AI 新增或修改：新建使用空值或程序默认，修改保持当前 JSON。导入器仍保留作者手工 JSON 的原值，不以“AI 输出”为由静默篡改。

## 外部 AI 地图草稿

- 地图沿用角色的外部 AI 协作方式：工坊下载零上下文提示词，用户在网页 AI 中完成多轮设计，再将最终完整 `MapEntry`
  JSON 粘贴回工坊。工坊不直接调用模型 API。
- 提示词逐项解释
  `author/desc/data`、递归节点、`名称检索词/描述/详情/图标/方位/子地图`、相对父级的坐标区间语义，以及 SVG 安全白名单和统一视觉要求。
- 外部 AI 应先按需访谈，再输出不含外部资源的自包含 HTML 方案稿，用于审阅层级、节点分布、名称与 SVG 风格；HTML 不进入工坊，不作为可保存字段，也不得代替最终 JSON。
- 用户确认方案后，AI 最终只输出完整 `MapEntry`
  JSON。新建导入创建地图草稿；修改导入完整覆盖当前地图草稿并保留 UUID。两者均复用地图 Schema 和 SVG 净化边界，失败不得产生或污染草稿。

## 可视化编辑契约

- 创意工坊的正式编辑入口必须一比一承载现有固定资产结构，不改变保存后的字段名、类型、层级和语义。
- 不提供自定义字段、任意嵌套结构或数据类型选择器；界面不能创建当前运行时无法可靠消费的数据。
- 各资产类型使用领域语义明确的固定表单或专用交互。JSON、对象、数组、注册表、UUID 和组装逻辑属于内部实现，不得成为普通创作者完成编辑所需理解的概念。
- UUID 仅作为内部引用键；正常列表、选择、冲突、引用问题和删除影响以资产名称、分类和上下文作为主要标识。
- 保存审阅必须展示可定位的资产级和字段级变化，不能只报告草稿与已保存数据不同。
- 重新读取、放弃草稿、收起或离开等可能丢失未保存内容的动作必须给出明确拦截和后果说明。
- 资产包安装在写入前必须展示内容、变更、冲突和引用完整性预览；无冲突不等于可以跳过用户确认。
- 角色资产可在包装层保存 `meta.avatar`、`meta.color` 与可选的
  `meta.avatarStyle`。头像接受普通 URL、SillyTavern 可读取的本地资源路径或上传图片经方形聚焦裁剪生成的 data
  URL；颜色是六位十六进制主题颜色。
- `meta` 随 v2 资产包按普通 JSON 字段导入导出。裁剪后的上传图片以内嵌 data
  URL 保存，因此会随角色资产包传递；头像加载失败时按角色 key 稳定生成默认头像，`avatarStyle` 可固定指定六种样式之一。
- 开发者角色目录按 `type + key`
  的身份事实聚合，但界面使用“角色身份 / 版本”语义；一级身份项展示名称、角色类型和引用摘要，二级抽屉展示作者、引用剧本和差异字段，默认收起。
- 开发者工作台开放地图资产目录。地图通过完整 `MapEntry` UTF-8
  JSON 新建、覆盖导入和导出；AI 辅助也只生成并导入同一格式。界面提供真实预览，不提供节点表单、拖拽改图或内置 JSON 文本编辑器。
- 地图节点 `图标` 是完整 `<svg>`
  字符串。导入和世界书读取必须按静态 SVG 安全子集校验，禁止脚本、事件属性、`foreignObject`、外部资源、危险 URL 和可执行样式；根标签允许精确的标准命名空间
  `xmlns="http://www.w3.org/2000/svg"`，其他命名空间值及 Markdown 链接形式仍拒绝。
- SVG 可在不同静态图形元素上分别声明安全的 `fill` / `stroke` 颜色，不限于 `currentColor`
  单色。渲染边界将这些已校验颜色转为带 `!important` 的内联声明，以免宿主页面样式覆盖地图图标。
- SVG 根节点显式 `width` / `height` 表示作者决定的地图视觉占地；`viewBox`
  只描述内部坐标系与比例，不自动换算为 CSS 像素。缺少显式尺寸时回退地图组件的默认图标尺寸。
- 地图渲染从 `方位` 中点取得语义位置；`x/y/z` 必须分别是恰含两个有限数字的
  `[min,max]`。正值分别代表东、北、上，每 1 点代表 1
  km；屏幕向右为东、向上为北。方位范围不反推 SVG 尺寸。当前层节点经过确定性的矩形碰撞布局得到仅用于显示的视觉位置；布局保持原始方向，使用 z 或稳定节点身份分离同点节点，不回写地图 JSON。
- SVG 随地图平面倍率同步缩放，缩小时保留最低可读尺寸；碰撞布局始终根据当前图标视觉尺寸维持安全间距。初始视图拟合使用布局后的完整节点包围盒。
- 地点详情锚定在所选图标旁，并根据图标所在画面侧自动换边；窄屏显示在图标下方。节点 `描述` 与 `详情`
  分别通过“简介 / 详细”Tab 展示，地图操作继续保留在同一详情浮层。进入地区、选择或前往等当前主要动作常驻；删除地图作为低频危险操作，经“更多地图操作”按需展开，不与主要动作并排挤压。
- 地图数据允许存在多个同级顶层节点。共享地图以不写入 JSON 的虚拟总根展示全部顶层地图，并允许通过面包屑或返回操作在不同顶层地图之间切换；不得默认固定进入记录中的第一个顶层节点。

## 删除与引用清理

- 普通删除在存在引用时应展示引用来源并阻止直接提交。
- 强制删除同步清理全部已知引用，不留下悬空 UUID。
- 集合引用移除数组成员。地图是单个完整嵌套资产，不存在节点级引用清理。
- 必填剧本引用被移除后允许为空，同时强制将剧本设为不可用。

## 资产包

- 文件为 UTF-8 JSON，包标识为 `dust-history-workshop-package`；当前导出版本号为 `2`。
- 包只承载当前分类注册表中的 JSON 或文本资产，不承载图片、音频等二进制文件。
- `assets` 按资源分类保存 UUID 到资产条目的映射；允许只包含开发者选择的任意资产。
- 用户工作区导出前必须允许按分类和具体资产选择。选择剧本时，内嵌世界、开场文本、主线、任务和事件随剧本对象直接导出；导出层只为角色、地图及全局共享资源扩展依赖闭包。单独选择普通资源不反向夹带引用它的剧本。
- 包不保存“完整”或“可玩”标记。导出端检查包自身引用，导入端以包内资产和目标主世界书资产的合并视图检查引用。
- 导入 UUID 不存在时新增；UUID 和内容均相同时跳过；UUID 相同但内容不同时由用户选择覆盖、跳过或复制。
- 复制产生新 UUID，并只重写包内仍存在的角色、地图和共享资源引用。
- 导入器只接受 v2 包；v1、地图节点分类和地图 `root` 拓扑均明确拒绝，不提供旧格式迁移。
- 冲突决策和重映射完成前不得写入；导入写入失败不得留下部分结果。
- 资产包选择器实时投影导出层计算的依赖闭包：手动选择与随剧本自动关联必须在具体资产行中区分显示，不能只在最终数量中暗示依赖已加入。

## 单剧本 JSON 往返

- 开发者工作台的单剧本导入导出使用完整 `ScenarioEntry` 纯 JSON，不带资产包的 `format/version/assets` 包装层。
- 导入先按当前剧本 Schema 完整校验并展示覆盖确认，再整体替换当前选中剧本的内存草稿，同时保留当前 UUID；非法 JSON、资产包或缺字段对象不得修改草稿，也不得直接写入世界书。
- 单剧本 JSON 只承载剧本对象本身。其内嵌世界、开场文本、主线、任务和事件自然随对象往返；角色、地图及共享资源仍由资产包负责跨项目迁移。

## 自动共享资源关联

- 世界经济、季节与节日、势力、种族对所有剧本自动全量关联；地图不自动关联，剧本显式保存一个地图 UUID。
- 底层 UUID 清单在读取和保存时同步，供资产影响分析使用，但不控制组装结果。
- 任务和事件按剧本内嵌数组保持顺序；角色采用下述互斥选择规则。

## 剧本角色互斥选择

- 2026-09-17 用户确认：同一剧本内，同一角色身份（`type + key`）只能选择一个版本；选择另一版本替换当前版本引用，不叠加多个版本。
- `user` 继续作为剧本单例：不同主角资产之间也互斥，可玩态必须恰有一个 `user`。
- 角色库保留所有版本；在剧本内替换所选版本不删除角色资产，不影响其他剧本的选择。
- 普通角色组装界面不再提供同一角色多个版本的优先级排序或覆盖链操作。底层仍使用 `内容配置.角色[]`
  保存引用，互斥规则不要求改变包格式。
- 实施状态：交互式角色选择器已按身份和版本互斥选择；存量覆盖链进入编辑时保留原先最后生效版本，组装器拒绝绕过编辑器产生的同身份重复引用。

## 运行时角色加入

- 来源限于当前主世界书 `<角色>配置` 中已有的 `user`、`主要角色` 或 `次要角色` 资产。
- 候选区必须先按角色身份聚合，再在身份下选择具体版本；普通角色身份为 `type + key`，所有 `user`
  资产共同构成一个单例身份。不得退化为“一份 UUID 资产一张角色卡”。
- 候选角色在加入或替换前可打开只读档案预览；预览复用尘史运行界面的共享角色面板及其生命、技能、术、关系、状态和物品组件，直接读取同一资产数据，不维护独立展示模型。
- 按资产 `type` 和 `key` 写入当前消息楼层 `stat_data.角色` 对应分桶。
- 运行态存在性从 `message_id: -1`
  的最新有效 MVU 状态读取；确认写入时仍以当前最后消息楼层为事务目标，避免最后楼层 ID 与有效变量读取入口不一致时漏判已有角色。
- 候选区默认隐藏运行态已有的同 `type + key`，`user` 按运行态单例执行同一规则；用户可取消勾选查看已有角色。
- 已有角色的动作显示为“替换”。三类角色均先展示字段差异并二次确认；确认后完整替换，取消则不写入。
- 写入运行态时，将资产包装层的 `meta` 复制为角色对象的 `meta`。三类角色的头像和颜色均供特殊对话框消费。
- 不修改世界书，不写入来源 UUID，不修改 `system.关注角色列表`，不执行字段级合并。
- 写入必须全有或全无，失败时恢复原运行态数据。

## 全局入口

- 收起状态显示带“创意工坊”文字的悬浮入口，避免仅凭抽象图标猜测用途。
- 悬浮入口沿用 `feature-moelotl` 小螈悬浮窗的鼠标/触摸拖拽语义：固定元素以明确 `top/left`
  定位，事件监听和视口约束必须来自入口元素的 `ownerDocument/defaultView`，不能使用脚本 iframe 的全局
  `document/window`；停靠位置保存到当前脚本变量，拖拽结束不得误触打开工坊。
- 展开后的移动端工作坊沿用尘史主界面的动态视口全屏规则：`100vh` 兼容回退、`100dvh`
  实际高度、安全区内边距和内部区域滚动，不能依赖挂载点百分比高度。
