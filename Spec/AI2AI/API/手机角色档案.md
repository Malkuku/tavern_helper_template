# 手机角色档案与解锁

手机角色档案读取当前聊天最新楼层的
`stat_data`。组织 App 的“观测”只有一个角色观测页；主要与次要角色沿用各自的运行态数据和解锁记录。旧脚本变量
`magicGirlPhoneLayout` 无需迁移。

## 我的档案

- 个人档案将 `角色.user.基础信息.身份`、`角色.user.基础信息.背景`、`角色.user.外貌`、`角色.user.性格`
  分块展示；背景、外貌和性格分别可编辑，保存时只写对应字段 `角色.user.基础信息.背景`、`角色.user.外貌` 或
  `角色.user.性格`。身份、当前评级与恶堕积分保持只读，积分在概览中配 SVG 图标展示；个人档案不显示金钱。
- 档案概览及魔女恶堕计划顶部的恶堕积分余额在鼠标悬停时，以组织口吻说明获取途径：完成组织任务并领奖，或魔法少女首次晋入新的恶堕等级时获得自动入账的一次性奖励。
- 保存时重新读取最新楼层，写入最新楼层的 `stat_data`，触发
  `mag_variable_update_ended`；聊天切换后取消过期操作，失败向页面显示原因。

## 角色观测

- `系统.已发现目标`
  为空时，手机桌面的魔女恶堕计划图标抖动并向周围散发粒子；点击 App 直接进入角色观测页的首位目标选择轮播：鹭见凛「白金裁定」、雨宫雫「绯丝舞者」、索菲亚「伤祷圣女」、小鸟游琉璃「千见」。每张卡片展示角色资源中可核实的身份与接触线索，以及选择后配发的道具。选择内容随页面滚动，不使用弹窗遮罩。只使用各角色的魔法少女形态 1 图片；隐藏角色林沐沐不参与首选。系统请求减少动态效果时停止图标动画。
- 首位目标选择轮播按图片原始宽高比完整展示角色图，不裁切人物。四张图在轮播挂载时加载并保留图片节点，切换角色时复用已加载图片。图片缺失或加载失败时保留原有背景，不显示占位图形或文字。
- 选择时在最新楼层记录
  `系统.已发现目标`，发放一项以目标 key 命名的专属初始接触任务和一件角色对应的 D 级掩护身份凭证，在正文追加
  `<systemLog>`；全部写入成功后跳转组织任务页。不主动创建玩家聊天消息或触发生成。写入失败时保留选择页并显示错误，不重复发放目标。同名道具规格不一致时拒绝选择。当前开局四位首选目标均有角色资源；旧运行态若缺少所选角色档案，观测页保留图片与待建立状态，待角色进入运行态后展示完整档案。
- 主要角色观测主视觉按角色 key 使用图片仓库的日常、魔法少女、恶堕形态图片；图片加载期间保留原有背景，缺失或失败时收为紧凑资料头，保留背景并显示姓名和已有身份，不显示占位图形或文字。无图的候选角色也使用紧凑资料头，身份只显示一次。恶堕形态仅在该角色
  `人设阶段.恶堕度.当前等级 >= 4`
  时可切换；等级下降时退出恶堕图。雨宫雫有两张魔法少女形态图，其余图片按实际资源数量展示。
- `系统.已发现目标`
  只记录玩家通过 App 选定的目标 key。独立变量更新规则不再根据正文中声明行动目标或发现魔法少女身份自动追加。缺少该字段的旧楼层按空目标名单展示；角色变量保留完整数据，`user`
  档案始终可见。
- 选定首位目标后，观测选择器同时列出运行态中尚未被选为目标的主要和次要角色。未选角色只显示日常立绘（有图时）、姓名、身份、背景和评级，不显示完整观测分页；花 20 点恶堕积分可选为目标。选取在最新楼层校验角色、余额和是否已选，扣费与追加目标名单一次性写回并记录正文日志；失败不扣费、不追加。主要角色背景改为免费展示，原 4 点解锁入口退出。
- 候选角色评级为 N 时，选取前确认该评级没有恶堕晋级积分奖励。林沐沐在候选页特判为普通人身份、N 级评级和伪装背景；选择她时依次经过 N 级奖励提示、亲妹妹提示和红色的最终确认。选取写入成功后短暂显示重复的红色“被发现了”及摇晃效果；减少动态效果设置下停止摇晃。真实恶堕奖励仍按角色运行态评级结算。
- 已发现且已有观测档案的主要角色，若
  `人设阶段.创伤稳定度.当前等级 <= 2`，组织 App 以黄色顶部应用通知警告并在观测导航显示黄色提示点。点击通知进入该角色的观测概览；通知可手动关闭，关闭不修改稳定度。顶部卡片按聊天、角色和当前等级只展示一次，手机重开或脚本重载不重复弹出；等级变化或恢复到 3 级以上后再次跌入警告范围时，可重新展示。次要角色没有创伤稳定度，不参与此警告。
- 主要角色三项人设阶段、次要角色恶堕度的等级变化另以顶部应用通知逐条提示，点击定位到对应角色；与低稳定度常驻警告分别处理。
- 手机角色编辑器进入时要求输入密码
  `987`，并提示可能包含剧情剧透；离开后重新进入须再次输入。解锁后列出主世界书中的全部角色资源及当前剧情中的全部次要角色，不按发现名单过滤。
- 观测页顶部以当前角色按钮和序号显示选择状态；点击后在页面内展开可搜索的角色选择列表，不使用额外浮层。列表按发现名单顺序展示已发现的主要角色、次要角色及已选但暂缺档案的首选目标；选中角色后关闭列表，共用“概览 / 身体 / 档案”三页，切换角色时返回概览。主要角色保留形态图片切换；无角色图的次要角色显示紧凑资料头。
- 主要角色概览依次展示创伤稳定度、好感度、恶堕度，并分别标明心理应对模式、关系亲近程度与恶堕进程；每项只读取
  `描述[String(当前等级)]`。创伤稳定度免费，好感度与恶堕度分别花 2 点按角色解锁；未解锁时隐藏等级、描述和进度。三项以不同颜色和轻微动效区分；已解锁阶段在卡片底部显示无数值经验条，不显示经验数值或下一等级数值。正经验按当前等级到下一等级的实际需求显示推进；可回退的阶段出现负经验时，底部仅显示从右向左的“回退”条；处于最低等级或恶堕度负经验时不显示可回退进度。最高等级的非负经验显示满条。身体页按角色花 2 点整体解锁，解锁后只读取各部位当前等级对应描述，不展示其他等级；各部位默认只显示当前状态，点开后显示特征和开发程度，次要角色的身体开发状态逐项分隔。观测页不展示角色在场或信号状态标签。
- 观测页三项人设阶段的名称即为世界观说明入口，支持鼠标悬停、键盘聚焦及触屏点按；未解锁的好感度、恶堕度也能查看通用说明，但不泄露当前等级和描述。说明使用面向玩家的叙述口吻：创伤稳定度呈现角色在伤痛面前的自我维系，并用红字警告过低可能引发灾难性后果；好感度呈现双方关系如何随经历变化；恶堕度呈现恶堕逐渐侵蚀角色，并用红字警告高恶堕值会污染魔法少女的魔力，使魔装发生不可逆转的变化。次要角色恶堕度沿用通用说明。
- 三项阶段的等级由手机脚本按[人设阶段经验与等级规则](./人设阶段经验与等级.md)结算；对话规则只增减有符号的 `累计经验`。
- 主要角色基础信息、整体印象、日常外貌与魔法形态免费。次要角色动态读取
  `角色.次要角色`，概览页显示名称键、身份、背景和外貌；恶堕度、身体状态、档案页的性格与能力按字段解锁。未解锁时不提前展示付费字段。
- 主要角色档案页将 `当前评级` 与身份、背景分开展示；旧存档缺失或为空时显示“未记录”。
- 我的档案与主、次角色观测使用共用 SVG 评级徽章：角色战力评级可识别 N（普通人）及 D～S 级，玩家组织评级沿用 D～S 级。悬停、键盘聚焦或触屏点按徽章显示对应说明；档案右侧的评级提示框向左展开，避免被页面右侧裁切。空评级继续显示“未记录”，其他非标准文本原样展示，不推断等级。
- 次要角色有 `人设阶段.恶堕度`
  时，概览页解锁后显示当前等级、当前等级对应描述及无数值经验条；旧存档缺少该字段时隐藏这一区块。
- 主要与次要角色的恶堕度卡片解锁后，在经验条下说明晋入下一级可获得的恶堕积分，金额按该角色当前评级读取晋级奖励规则；评级未确定时提示奖励待确认，评级无效时提示无法预览，达到 6 级后提示晋级奖励已达上限。未解锁时不展示当前等级或奖励金额。
- 次要角色概览页将 `当前评级`
  与身份、背景分开展示；字段缺失或为空时显示“未记录”。手机角色编辑器可分别修改评级与身份、背景。
- 档案页按身份、外观、人物内面、能力与创伤组织信息，身份和评级合并展示，外观三项归在一组；付费字段继续按原字段独立解锁。主要角色的核心能力保留静态能力描述，`魔法少女能力.核心能力限制`只按当前`人设阶段.创伤稳定度.当前等级`精确取对应一项作为“此刻的能力边界”，缺失时提示当前阶段暂无记录，不展示其他等级的限制。核心能力卡片始终说明创伤稳定度会影响能力表现；这段通用说明不泄露未解锁内容。次要角色档案按人物记录和能力记录分组。
- 解锁价格如下。日常外貌与魔法形态默认可看，旧存档中已有的对应解锁记录无需迁移：

| 主要角色 | 身体状态       |                2 |

## 持久化与失败语义

- 手机角色编辑器另提供当前剧情次要角色列表，可直接编辑 `角色.次要角色.<名称>`
  的全部常用字段并删除该角色。保存或删除仅修改当前楼层变量，不修改主世界书角色资源；操作前确认，提交时重新读取最新楼层并校验原角色未变化，和档案、微信写入共用顺序队列。删除只移除角色变量，保留既有微信历史与账号。

- `手机.档案解锁` 是可选字段，旧存档缺失时视为未解锁。结构为
  `{ 主要角色?: Record<角色key, string[]>, 次要角色?: Record<角色key, string[]> }`。新开局不必预填。
- 每次解锁在同一份最新 `stat_data` 副本中校验角色、字段与余额，然后扣减 `角色.user.恶堕积分`
  并记录字段，最后一次性写回。已解锁字段不重复扣费；余额不足、字段非法或角色消失时不写回。
- 档案编辑、解锁和微信写入共用顺序队列，避免同楼层并发覆盖。余额与解锁记录只随聊天楼层存档，不放入全局或脚本变量。
