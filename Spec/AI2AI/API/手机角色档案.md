# 手机角色档案与解锁

手机角色档案读取当前聊天最新楼层的
`stat_data`。组织 App 的“观测”只有一个角色观测页；主要与次要角色沿用各自的运行态数据和解锁记录。旧脚本变量
`magicGirlPhoneLayout` 无需迁移。

## 我的档案

- 只允许编辑 `角色.user.基础信息`；当前评级、金钱和恶堕积分保持只读。
- 保存时重新读取最新楼层，写入最新楼层的 `stat_data`，触发
  `mag_variable_update_ended`；聊天切换后取消过期操作，失败向页面显示原因。

## 角色观测

- `系统.已发现目标`
  为空时，手机桌面的魔女恶堕计划图标抖动并向周围散发粒子；点击 App 直接进入角色观测页的首位目标选择轮播：鹭见凛「白金裁定」、雨宫雫「绯丝舞者」、索菲亚「伤祷圣女」、小鸟游琉璃「千见」。每张卡片展示角色资源中可核实的身份与接触线索，以及选择后配发的道具。选择内容随页面滚动，不使用弹窗遮罩。只使用各角色的魔法少女形态 1 图片；隐藏角色林沐沐不参与首选。系统请求减少动态效果时停止图标动画。
- 首位目标选择轮播按图片原始宽高比完整展示角色图，不裁切人物。四张图在轮播挂载时加载并保留图片节点，切换角色时复用已加载图片。
- 选择时在最新楼层记录
  `系统.已发现目标`，发放一项以目标 key 命名的专属初始接触任务和一件角色对应的 D 级普通道具，在正文追加
  `<systemLog>`；全部写入成功后跳转组织任务页。不主动创建玩家聊天消息或触发生成。写入失败时保留选择页并显示错误，不重复发放目标。同名道具规格不一致时拒绝选择。当前开局四位首选目标均有角色资源；旧运行态若缺少所选角色档案，观测页保留图片与待建立状态，待角色进入运行态后展示完整档案。
- 主要角色观测主视觉按角色 key 使用图片仓库的日常、魔法少女、恶堕形态图片。恶堕形态仅在该角色
  `人设阶段.恶堕度.当前等级 >= 4`
  时可切换；等级下降时退出恶堕图。雨宫雫有两张魔法少女形态图，其余图片按实际资源数量展示。
- 角色观测页和手机角色编辑器只列出 `系统.已发现目标` 中的角色 key；`user`
  档案始终可见。缺少发现名单的旧楼层按空名单展示。发现名单由独立变量规则维护，编辑器加入角色和正文人物收录不自动公开角色；角色变量保留完整数据。
- 统一选择器按发现名单顺序展示已发现的主要角色、次要角色及已选但暂缺档案的首选目标；选中角色后共用“概览 / 身体 / 档案”三页，切换角色时返回概览。主要角色保留形态图片切换；无角色图的次要角色显示紧凑资料头。
- 主要角色概览依次展示创伤稳定度、好感度、恶堕度；每项只读取
  `描述[String(当前等级)]`。身体页只读取各部位当前等级对应描述，不展示其他等级；当前状态、特征和开发程度分块标注，次要角色的身体开发状态逐项分隔。经验按当前等级的相邻等级需求显示进度；可降级指标的负余额显示向低一级的进度，恶堕度的负余额显示欠账，等级端点显示经验余额。观测页不展示角色在场或信号状态标签。
- 三项阶段的等级由手机脚本按[人设阶段经验与等级规则](./人设阶段经验与等级.md)结算；对话规则只增减有符号的 `累计经验`。
- 主要角色基础信息、整体印象和三项当前等级表现免费。次要角色动态读取
  `角色.次要角色`，概览页显示名称键、身份、背景和外貌；档案页的性格与能力按字段解锁，并显示身体开发状态列表。列表不提前展示付费字段。
- 主要角色档案页将 `当前评级` 与身份、背景分开展示；旧存档缺失或为空时显示“未记录”。
- 次要角色有 `人设阶段.恶堕度`
  时，概览页免费显示当前等级、当前等级经验进度或欠账及当前等级对应描述；旧存档缺少该字段时隐藏这一区块。
- 次要角色概览页将 `当前评级`
  与身份、背景分开展示；字段缺失或为空时显示“未记录”。手机角色编辑器可分别修改评级与身份、背景。
- 解锁价格参考“魔法少女恶堕/更新规则”中 D 级普通任务 3～6、高风险任务 7～10 积分和一级技能 20～35 积分的经济尺度：

| 主要角色 | 日常外貌         |                3 |
| 主要角色 | 魔法形态（正常） |                5 |
| 主要角色 | 性格             |                5 |
| 主要角色 | 背景             |                8 |

## 持久化与失败语义

- 手机角色编辑器另提供当前剧情次要角色列表，可直接编辑 `角色.次要角色.<名称>`
  的全部常用字段并删除该角色。保存或删除仅修改当前楼层变量，不修改主世界书角色资源；操作前确认，提交时重新读取最新楼层并校验原角色未变化，和档案、微信写入共用顺序队列。删除只移除角色变量，保留既有微信历史与账号。

- `手机.档案解锁` 是可选字段，旧存档缺失时视为未解锁。结构为
  `{ 主要角色?: Record<角色key, string[]>, 次要角色?: Record<角色key, string[]> }`。新开局不必预填。
- 每次解锁在同一份最新 `stat_data` 副本中校验角色、字段与余额，然后扣减 `角色.user.恶堕积分`
  并记录字段，最后一次性写回。已解锁字段不重复扣费；余额不足、字段非法或角色消失时不写回。
- 档案编辑、解锁和微信写入共用顺序队列，避免同楼层并发覆盖。余额与解锁记录只随聊天楼层存档，不放入全局或脚本变量。
