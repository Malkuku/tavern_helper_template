# 创意工坊字段与界面映射

## 产品边界

正式工坊只有“角色”和“剧本”两个创作领域，不再把底层注册表分类暴露为并列编辑器。UUID、注册表、共享 UUID 清单和资产包重映射是素材管理内部机制。

- 可创建与编辑：`user` / 主要角色 / 次要角色，剧本元设置，初始世界状态，角色组装，开场文本，主线，任务和事件。
- 只读自动装配摘要：地图、世界经济、季节与节日、势力、种族。界面不提供这些分类的创建、编辑或选择控件。
- 地图是 `author, desc, data` 包装的唯一完整嵌套地图；`data`
  直接是组装器消费的最终内容。正式界面不存在地图资产或地图节点选择器；剧本初始地点可以通过完整地图的地点选择器写入
  `地图索引`。

## 正式交互模型

- 2026-09-17 用户确认：正式工坊采用面向创作任务的角色档案工作台与剧本编排工作台，替代将全部字段纵向铺开的长表单。现有
  `RoleEditor.vue` 和 `ScenarioEditor.vue` 的长表单结构是待取缔实现，不作为新版界面基线。
- 角色档案以头像和身份摘要作为稳定入口，主体按概览、人格关系、能力技能、状态物品和语料等领域切换；动态集合使用卡片、条目编辑器或详情面板承载。
- 创作者工作区中的角色档案默认可编辑，不设置没有真实权限意义的阅读/编辑切换。关系、技能、特殊状态、物品、术与语料以完成品视觉作为默认外观；点击具体对象或字段后在原位置显示编辑 affordance，并在原布局中完成新增、修改和删除。不建立 JSON 编辑器、属性侧栏、覆盖式抽屉、弹窗编辑器或独立聚焦编辑页。
- 原位编辑只修改同一份内存草稿，不逐字段持久化，也不绕过现有差异审阅和原子保存。运行时查看与工坊编辑共享组件结构、样式和图标，由
  `view/edit` 模式决定控件。
- 角色选择使用独立交互式选择器：支持搜索和类型筛选，先选择角色身份，再在二级区域互斥选择具体版本，同时提供角色详情、版本差异、已选阵容和明确的确认动作。该选择器优先作为剧本组装的权威入口，并可供后续角色阅览和运行时加入复用。
- 剧本编辑以自由编排工作台为主。概览首先展示剧本身份、可玩状态、当前阵容和叙事骨架；角色、世界状态、开场、主线、任务和事件作为可进入的模块。首次创建可以提供辅助向导，但向导不形成第二套数据或编辑流程。
- 剧本资源侧栏条目复用剧本所选视觉方案的共享 SVG；是否可玩由 SVG 状态徽标表达，标题下显示剧本简介，不重复图标已经表达的视觉方案名称，也不显示“可玩 / 编辑中”文字。
- 桌面端使用主工作区与上下文详情面板；移动端沿用相同信息架构切换为全屏分步页面，不将桌面多栏简单纵向堆叠。
- 移动端切换不同类型或不同资产的角色时，编辑器内部活动分区必须随角色实例重置；若当前分区不适用于目标类型（例如次要角色没有“人格关系”），回到“角色档案”。旧主要角色缺少可选集合字段时按空集合展示，不因浏览而静默补写草稿。
- 参考同类产品只采用信息架构和交互模式，不复制与尘史视觉、现有数据契约或宿主环境不相容的皮肤和功能。
- 工坊要求复用尘史既有视觉或提供真实预览时，必须遵守[视觉复用与参考保真规则](../视觉复用与参考保真规则.md)：原页面与工坊直接消费同一权威组件，不得重画近似实现。

## 剧本映射

| 界面分区     | 字段                                                  | 交互与规则                                                                                                                                                            |
| ------------ | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 元设置       | `key, desc, author, 视觉方案, 自定义主角, 可用`       | 视觉方案从共享十四方案注册表选择；主题选择不显示状态徽标，可玩状态仅由剧本资源侧栏展示。自定义主角使用“固定主角 / 允许自定义”双态选择；引用不完整时保存会保持不可用。 |
| 初始世界状态 | `内容配置.世界.时间/地点/季节/天气/地图索引/危险场景` | 在剧本内直接编辑并随剧本保存；`地图索引` 是运行时地点名，不是 UUID。                                                                                                  |
| 角色组装     | `内容配置.角色[]`                                     | 同一角色身份（`type + key`）的版本互斥；选择另一版本替换当前引用，不追加覆盖链。所有 `user` 资产之间也互斥，必须恰有一个 `user` 才可玩。                              |
| 开场文本     | `内容配置.开场文本: string`                           | 大型多行文本，保留 `<user>`、`<options>` 等标记原文。                                                                                                                 |
| 主线         | `内容配置.主线`                                       | 除保留键 `meta` 外按名称组织任意 JSON 条目；`meta` 保存组件树、数据绑定与视觉变体。业务条目不假定固定子字段。                                                         |
| 任务         | `内容配置.任务[]`                                     | 内嵌有序 `{ key, data }`，data 为 `描述/目标/阻碍/期望奖励/取得成果[]`。                                                                                              |
| 事件         | `内容配置.事件[]`                                     | 内嵌有序 `{ key, data }`，data 为 `描述/作用/进度`。                                                                                                                  |

世界、开场文本、主线、任务和事件是剧本内嵌字段，不拥有独立 UUID、注册表、选择器或跨剧本共享语义。新建、复制、导入和导出剧本时作为剧本对象整体处理。

主线的业务结构由具体剧本决定；运行时已有的 `描述/警惕度/详细/已交融的魂质`
只是部分主线可能采用的字段，不是主线 Schema。工坊必须保留未知字段、嵌套对象、数组、标量类型和对象键顺序。

`主线.meta` 为保留视图键，不作为一条主线参与 EJS/MVU 业务处理。其 `layouts`
按主线名称保存组件树；组件包含稳定 id、类型、数据路径绑定、视觉变体及可选子组件。缺少 `meta`
时工坊补齐默认编排，玩家运行时只做兼容渲染而不写回。

角色版本互斥已于 2026-09-17 实现。交互式选择器按角色身份展示具体版本，选择新版本替换当前引用；存量覆盖链在进入编辑时归并为原先最后生效版本，替换引用不删除角色库中的其他版本。

## 角色映射

`type` 只取 `user` / 主要角色 / 次要角色。类型转换前显示将删除的不适用字段。角色档案工作台按领域组织：

| 领域                 | 字段                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 基本资料、外貌与背景 | `key, author, desc, type`；`user.key` 恒为只读的 `user`；主要/次要的 `姓名/名称检索词[]/区域检索词[]/在场`；`user`/主要的 `年龄/当前身份/外貌[]/背景[]`；主要的 `当前想法/外貌概括/战斗风格[]/语料`；次要的 `简介/性格标签[]`。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 视觉元数据           | `meta.avatar/meta.color/meta.avatarStyle?`；头像接受 URL、SillyTavern 本地资源路径或上传图片经方形聚焦裁剪生成的 data URL，并在头像主题展开栏内提供最终对话效果预览。非空 `avatar` 是头像的优先来源并按原值保存；`avatarStyle` 在无图或图片加载失败时用于角色列表与对话框的同款回退头像。空头像按角色 key 稳定生成默认样式，也可从六种样式中固定选择。主题颜色使用六位十六进制值，统一用于所有共享角色头像的外框薄环，以及对话中的名称和引号；角色目录、选择器、档案、剧本阵容与对话预览不得各自保留固定金色头像框。希尔作为露娜的双重人格不通过常规角色元数据配置；以希尔或希尔·菲诺尔发言时固定显示为希尔·菲诺尔，使用历史专属头像 URL `https://gitgud.io/mouse789/dust-laden-obdurant/-/raw/main/头像/希尔.webp` 与主题色 `#A8B9CC`。 |
| 性格与关系           | `性格.社交表现/行动逻辑/思维习惯/人际距离/道德底色`；`人际关系.{对象}.认知了解/情感羁绊/利益纽带`；`性经验`。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 基础状态、技能与术   | `基础数值.力量/敏捷/智慧/魅力` 和 `生命状态.{生命\|体力\|精神}.最大值` 由 Beta `MvuZod.js` 根据术等级派生，只读展示；工坊资产中的三个当前值固定跟随对应最大值，不提供独立编辑。该状态展示与技能、术合并在“技能与术”分区。术的性相固定为灯、铸、刃、冬、心、杯、蛾、启，采用开局加点式增减交互；等级为 0 的性相不写入角色 JSON。                                                                                                                                                                                                                                                                                                                                                                                                          |
| 特殊状态与物品       | `user` 的 `金钱/缥缈异质` 置于分区顶部；其后为特殊状态与物品。物品详情嵌入角色分区，遮罩和卡片光效不得越出物品模块覆盖工坊导航、保存栏或对话框；不改变名称键与固定字段结构。物品类型严格限定为器具、药食、证明、秘传、仪式、杂物；普通物品品质限定为凡庸、遗物、佚品、珍品、禁忌、神造、未知，秘传与仪式品质限定为遗片、佚存、残卷、蛀损、完帙、未知。载入草稿时，非法类型回落为杂物，非法普通品质回落为凡庸，非法文献品质回落为遗片，并作为待保存差异呈现。                                                                                                                                                                                                                                                                             |

动态集合按业务名称建键，支持新增、删除、复制、排序和折叠；子字段仍是固定契约，不是任意 JSON 编辑。读取—保存—重读必须保留未知合法字段、原类型和集合顺序。动态集合与角色外观使用和移动工作区一致的
`720px`
断点；移动端必须允许卡片、标题、操作按钮及展开内容沿完整祖先宽度链收缩、换行，不得以桌面最小内容宽度撑出横向滚动。角色外观在移动端切换为单列，头像选项自身横向滚动，对话预览在剩余宽度内收缩。语料场景名和语句均允许无空格长文本在卡片或只读角色面板的可用宽度内断行，不得撑出横向滚动。

## 派生展示与运行时

- 筛选标签由 `type`、`key`、名称/区域检索词、作者、剧本引用和运行时存在状态派生；不持久化 `tags`。
- 同 `type + key`
  角色聚合为一个“角色身份”，二级版本抽屉默认收起；具体版本显示作者、引用剧本、素材说明及选定剧本的当前生效版本，UUID 不作为普通标题。
- 剧本“角色阵容”卡片统一显示角色名称、作者和素材说明，不用角色类型占用副字段；每张阵容卡提供独立只读档案预览，预览直接复用运行时角色面板且不进入角色资源编辑态。创作者角色资源目录继续负责身份与版本组织，不承担该预览入口。
- 桌面端将草稿状态、引用检查和当前对象收为常驻摘要条；当前角色头像、类型、作者、引用剧本和具体版本按需展开。共享资源自动装配是底层固定规则，不展示无行动价值的分类数量面板。移动端“检查”面板直接显示完整且可行动的详情，不以抽象规则说明代替当前对象。
- 运行时候选默认隐藏已存在的同 `type + key`，`user`
  按单例执行同一规则；用户可取消勾选查看已有角色。玩家工作区不提供派生标签筛选。
- 三类已有角色均在覆盖前显示字段差异并二次确认；确认后整体替换，取消不写入，失败恢复原数据。
- 当前角色的未保存字段按角色档案分区标记，保存审阅继续显示资产和字段级差异；所有运行时写入保持全有或全无。
- 移动端开发工作区使用“资源 / 编辑 / 检查”三个互斥面板；选中或新建资产后进入编辑面板，草稿计数、保存入口和主世界书连接状态持续可见。
- 角色域提供外部 AI 草稿入口，支持新建和修改两种上下文。提示词只注入与角色设计直接相关的世界观：八大准则、八种术说明、物品参考表和纯运行态势力 JSON；不注入地图详情、经济、季节或种族。其余内容以字段职责、格式约束、正反例、防八股规则及访谈流程形成零上下文任务单；AI 可先向用户追问，信息充分后再输出 JSON。新建主要/次要角色的名称与区域检索词默认使用
  `$all`，名称检索词可由 AI 根据姓名、别名和称呼完善，区域词没有扁平地图节点清单时不得臆造。修改时额外导出当前角色的单个
  `stat_data` 对象。导入保留检索词原值，完整覆盖当前资产数据与运行态
  `meta`，但保留 UUID、类型、key、作者、素材说明及工坊专用头像样式；基础数值及生命状态按术等级重算。

## 格式边界

开发者资产包工具仍可导入、导出底层锁定资源，但不形成普通用户编辑入口。只接受 v2 资产包和 `data`
完整嵌套地图；v1 资产包、地图 `root` 拓扑及 `<地图节点>配置` 均明确拒绝。
