# 魔法少女世界书变量初始化

每次打开手机时，Store 从当前角色绑定的主世界书读取以下条目；切换聊天只清理旧视图并取消过期检查，等待下一次打开手机再初始化：

- `当前世界书版本`：读取唯一的 `version: x.y.z` 行，写入 `stat_data.系统.版本`。
- `[initvar]`：读取其中的全局初始字段；当前条目只有作者信息时，按空配置处理，由类型默认值补齐基础容器。
- 所有名称以 `<人设配置>` 开头的条目：`user` 写入 `角色.user`，其他名称写入 `角色.主要角色.<名称>`。`<人设配置>user` 也可声明 `$.仓库` 与 `$.任务`。

配置使用 `<JSON path="$.路径" type="string|number|boolean|json" dynamic="true">内容</JSON>`。`dynamic` 是配置元数据，不写入运行时变量。所有有效标签均按路径录入，即使字段暂未出现在前端 TypeScript 接口中。角色名称与数量由世界书决定。

合并规则：

1. 首次初始化或人物条目不存在时，完整写入其标签字段，包括动态字段默认值。
2. `系统.版本` 不同时，普通字段采用当前世界书值；动态字段保持变量中的值，只补缺失字段。动态 JSON 对象递归补缺键，不替换已有叶子和数组。
3. 版本相同时，仅补缺失字段。未出现在任何配置标签中的现有变量通常保留；已从类型契约移除的 `系统.商店待刷新`、`任务待刷新`、`技能待刷新` 会清除。
4. 类型契约中的基础容器，以及世界时间、地点、天气、微信空结构，在缺失时补默认值；不会覆盖已有值。
5. 缺少关键条目、重复条目或标签解析失败时，本次不写入 MVU，Store 在控制台报告错误。成功合并后只写当前楼层一次，并发出 `mag_variable_update_ended`。

旧存档若仍将 `角色.user.基础信息` 或主要角色的 `基础信息` 保存为对象，合并时按原有键值转成多行字符串，再应用当前模板。这个转换保留动态内容，使运行时符合新的字符串字段契约。
