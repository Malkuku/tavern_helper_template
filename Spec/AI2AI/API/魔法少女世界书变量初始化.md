# 魔法少女唯一开局变量组装

首次打开手机时，Store 读取当前角色主世界书中的三个 JSON 条目：`<配置>唯一开局`、`<配置>角色资源`、`<配置>地图资源`。当前只有一个开局；小手机只提供角色资源编辑，不提供剧本和地图编辑。数据边界沿用尘史创意工坊的固定数据、开场内容配置、资源注册表与 UUID 引用组装方式。

- `唯一开局.固定数据`：各开局共享的系统初值与空容器，含空 `仓库`、商店、任务和手机微信结构；不包含世界、角色或地图。
- `唯一开局.开场白`：UUID 到开局资产的注册表，必须恰有一项且 `可用: true`。资产含 `author/key/desc/内容配置`；内容配置提供初始 `世界`、初始 `仓库`、角色 UUID 列表与地图 UUID。
- `角色资源`：UUID 到角色资产的注册表。资产含 `author/key/desc/type/data`，可带 `meta`（`avatar`、六位十六进制 `color`、可选 `avatarStyle`）；`type` 为 `user`、`主要角色` 或 `次要角色`，`data` 为完整角色对象。`user` 必须恰好一个，其 `key` 必须为 `user`。同类型同 key 不得重复引用。
- 当前角色数据中，`user.基础信息` 含身份列表和背景，外貌、性格为独立文本；主要角色的 `基础信息` 含姓名、身份列表和背景，身体的特殊状态及四个部位直接位于 `身体` 下，部位含特征、开发程度与当前状态。主要角色不再提供独立背景或变身布尔字段。
- 次要角色以 `角色.次要角色.<名称>` 的键表示名称；对象内含名称检索词、区域检索词、在场、身份列表、背景、外貌、性格、身体开发状态列表和能力描述列表，不再含独立的 `名称` 或 `简介` 字段。
- `地图资源`：UUID 到地图资产的注册表。资产含 `author/desc/data`，`data` 是完整嵌套地图。当前开局直接引用 `系统配置/地图资源.json` 中的简明彩色 SVG 示例地图；地图资源是唯一数据来源。

组装器先校验开局与资源包装层，再按引用构造 `stat_data`。角色资产 `meta` 随数据写入运行态；`user` 写入单例，其他角色进入对应类型分桶；地图和开局仓库写入对应字段。初始微信账号由 `user` 和主要角色生成，昵称分别为“我”和角色名称，头像取角色 `meta.avatar`，缺图时由角色键、`avatarStyle` 和主题色生成稳定默认头像，并建立双向好友；不预建会话或消息。完整结果由 `initialDataSchema.ts` 按 `types.ts` 的 `stat_data` 契约校验，非法或多余字段不静默丢弃。校验成功后写入当前楼层一次，并发出 `mag_variable_update_ended`。

只有当前楼层 `stat_data` 恰好为 `{ "作者": 987 }` 时才执行组装；其他对象不触发组装，不覆盖游玩值。`stat_data` 缺失或类型无效时报错。缺失、重复或非法资源，以及不符合变量契约的组装结果，都会阻止本次 MVU 写入并在控制台报告错误。叙事仍由 `角色列表` 从当前 `stat_data.角色` 提取，不使用逐字段人设标签。当前没有旧存档迁移要求。

物品与技能对象可携带完整 SVG `图标` 字段。新开局组装校验其安全 SVG 子集；现有资源若尚无图标仍可组装，手机显示默认图形，后续资源更新可逐项补入。

新开局地图节点必须携带安全的完整 SVG `图标`，可使用元素级彩色填充与描边。旧楼层地图节点缺图标时，手机地图显示默认图形，不迁移旧楼层。
