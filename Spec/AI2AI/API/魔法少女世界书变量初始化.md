# 魔法少女唯一开局变量组装

首次打开手机时，Store 读取当前角色主世界书中的三个 JSON 条目：`<配置>唯一开局`、`<配置>角色资源`、`<配置>地图资源`。当前只有一个开局；小手机只提供角色资源编辑，不提供剧本和地图编辑。数据边界沿用尘史创意工坊的固定数据、开场内容配置、资源注册表与 UUID 引用组装方式。

- `唯一开局.固定数据`：各开局共享的系统初值与空容器，含 `系统.已发现目标: []`、空
  `仓库`、商店、已接任务、任务候选和手机微信结构；不包含世界、角色或地图。组装器根据开局世界时间填充最近两周任务统计的起始周与空白本周记录。
- `唯一开局.开场白`：UUID 到开局资产的注册表，必须恰有一项且 `可用: true`。资产含
  `author/key/desc/内容配置`；内容配置提供初始 `世界`、初始 `仓库`、角色 UUID 列表与地图 UUID。
- `角色资源`：UUID 到角色资产的注册表。资产含 `author/key/desc/type/data`，可带 `meta`（`avatar`、六位十六进制
  `color`、可选 `avatarStyle`）；`type` 为 `user`、`主要角色` 或 `次要角色`，`data` 为完整角色对象。`user`
  必须恰好一个，其 `key` 必须为 `user`。同类型同 key 不得重复引用。
- 当前角色数据中，`user.基础信息` 含身份列表和背景，外貌、性格为独立文本；主要角色的 `基础信息`
  含姓名、身份列表和背景，身体的特殊状态及四个部位直接位于 `身体`
  下，部位含特征、开发程度与当前状态。主要角色不再提供独立背景或变身布尔字段。主要角色另有独立的`当前评级`字符串；现有角色资源中的 A/S 评级已从身份描述拆出，身份原有的其他信息保留。
- 次要角色以 `角色.次要角色.<名称>`
  的键表示名称；对象内含名称检索词、区域检索词、在场、身份列表、独立的`当前评级`、背景、外貌、性格、身体开发状态列表和能力描述列表，不再含独立的
  `名称` 或 `简介` 字段。新加入的次要角色另含 `人设阶段.恶堕度`，结构与主要角色的恶堕度相同。

主世界书的禁用条目 `<模板>通用恶堕值`
保存通用初始恶堕度 JSON：`当前等级`、`累计经验`、`描述`（0～6 级）。唯一开局引用次要角色、手机新建角色资源、将资源加入当前剧情以及正文新人物收录时，缺少该字段的次要角色从模板复制一份；角色资源已有专属恶堕度时使用其描述。替换当前剧情角色时保留原有当前等级和累计经验，描述取新资源版本。模板缺失或无效时拒绝新增，不写入半成品角色。已有存档中的旧次要角色不自动迁移。新加入的主要角色和次要角色都具有独立`当前评级`字符串；未知时为空字符串。身份与背景保留自身描述职责，评级不从其中推断。旧存档缺少评级时继续可读。

- `地图资源`：UUID 到地图资产的注册表。资产含 `author/desc/data`，`data` 是完整嵌套地图。当前开局直接引用
  `系统配置/地图资源.json` 中的完整嵌套地图；地图资源是唯一数据来源。

独立的次要角色生成页读取世界书 `<MinorCharInfo>` 中的 `{ "角色": [...] }`。每个生成项含
`名称`、`名称检索词`、`身份`、`当前评级`、`背景`、`外貌`、`性格`、`身体开发状态`、`能力描述`；多角色可切换，档案按人物概览、性格与状态、能力档案分页，窄屏保留分页交互。收录时以
`名称` 为运行态字典键，不把 `名称` 写入对象。收录页补入当前地图索引作为区域检索词（缺失时为空数组），并设置
`在场: true`；已有主要或次要角色同名时不覆盖。输入格式无效时不写入。收录时也从 `<模板>通用恶堕值` 补入初始恶堕度。

组装器先校验开局与资源包装层，再按引用构造 `stat_data`。角色资产 `meta` 随数据写入运行态；`user`
写入单例，其他角色进入对应类型分桶；地图和开局仓库写入对应字段。初始微信保留固定数据中配置的账号、好友关系与会话；缺少
`user` 账号时仅补建 `user`，不按主要角色批量建号或互加好友。已有账号缺少头像时取对应角色的
`meta.avatar`，无对应角色或缺图时由账号键、`avatarStyle` 和主题色生成稳定默认头像。完整结果由 `initialDataSchema.ts` 按
`types.ts` 的 `stat_data` 契约校验，非法或多余字段不静默丢弃。校验成功后写入当前楼层一次，并发出
`mag_variable_update_ended`。

只有当前楼层 `stat_data` 恰好为 `{ "作者": 987 }` 时才执行组装；其他对象不触发组装，不覆盖游玩值。`stat_data`
缺失或类型无效时报错。缺失、重复或非法资源，以及不符合变量契约的组装结果，都会阻止本次 MVU 写入并在控制台报告错误。叙事仍由
`角色列表` 从当前 `stat_data.角色` 提取，不使用逐字段人设标签。当前没有旧存档迁移要求。

`系统.已发现目标` 存放已公开角色的精确 key，通常与 `角色.主要角色` 或 `角色.次要角色`
中的 key 对应，由独立变量规则更新。角色收录和手机手动加入只写角色档案，不自动加入发现名单。`user`
始终可见；初始空名单不会删除开局预置的隐藏角色。

观测页的首位目标选择也会将所选 key 写入
`系统.已发现目标`。当前唯一开局已引用四位首选目标的角色资源；旧运行态若缺少所选角色档案，观测页显示图片和待建立档案状态，角色资源进入运行态后按名单正常展示。

物品与技能对象可携带完整 SVG `图标`
字段。新开局组装校验其安全 SVG 子集；现有资源若尚无图标仍可组装，手机显示默认图形，后续资源更新可逐项补入。初始
`user.技能`
使用单版本结构，包含完整`描述`、`作用`、`战力评级贡献`、`适用评级`和累计`价格`；赠送技能价格为 0。系统沿用技能下次刷新时间和成功刷新次数，供手机脚本计算报价。

新开局地图节点必须携带安全的完整 SVG
`图标`，可使用元素级彩色填充与描边。旧楼层地图节点缺图标时，手机地图显示默认图形，不迁移旧楼层。
