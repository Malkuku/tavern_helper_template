# 微信未读与消息弹窗

## 状态

实现与定向验证完成；宿主视觉与事件时序待联调。

## 目标与范围

微信收到他人新消息时显示未读红点和可点击的消息弹窗。手机打开时弹窗位于手机屏幕顶部；手机关闭时弹窗位于宿主页面顶部。点击弹窗打开手机并直达对应聊天。

## 关键设计决定

- 以当前楼层 `stat_data.手机.微信` 的会话消息流为唯一消息来源；只对新增且发送者不是 `user`
  的普通消息弹窗。重放日志和其他变量更新不重复弹窗。
- 以脚本变量保存按聊天 ID、会话 key 区分的已读楼层；首次启用时把现有历史作为基线，不为历史消息弹窗。打开会话即标记已读。消息处于当前打开的会话时直接视为已读。
- 红点显示在手机悬浮入口、桌面微信图标及微信会话列表；文件夹中的微信图标同样显示。免打扰会话保留红点，但不弹出预览。
- 弹窗复用会话名称、头像及消息内容摘要；点击后只在该会话存在且包含 user 时导航。聊天切换清理瞬时弹窗，不串用其他聊天的已读状态。
- 弹窗手动关闭，点击后关闭；不自行定义自动收起时长。

## Agent 分工

- 当前 Agent：设计、实现、定向验证和文档收口；不设独立验收角色。

## 验收标准

- 他人消息在手机打开与关闭两种状态下分别显示在正确位置；点击进入对应聊天并清除该会话红点。
- 微信图标、悬浮入口和会话行显示未读红点；只清除已打开会话的未读。
- user 自发消息、旧日志重放、非消息操作、初次加载历史不弹窗；免打扰不弹窗但仍有未读红点。
- 聊天切换与脚本重载不产生跨聊天误报或历史弹窗。
