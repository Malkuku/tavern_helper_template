# 微信会话消息流

## 状态

实现与定向验证完成；宿主内规则生成和界面时序待联调。

## 目标与范围

将微信会话 `消息[]` 扩为聊天与行为按序保存的消息流，覆盖 NPC 主动和跨会话聊天、好友申请与处理、拍一拍、建群与邀请、名片、红包和转账处理。同步修改手机界面、正文增量应用、两份世界书规则及 `statdata.json` 初始化文件。

## 关键设计决定

- 不增加消息 ID；会话数组顺序是历史顺序。红包及转账处理追加操作项，并更新原消息卡片状态；目标选择最近的符合条件且未处理的消息。
- 账号保留当前好友关系；好友申请、通过、拒绝写入双方私聊消息流。拒绝后允许再次申请；待处理申请从最近一轮操作推导。
- 非好友不能发送普通私聊消息，群成员只能邀请自己的好友。正文与界面使用同一应用校验；整份日志原子应用。
- 允许群聊重名，规则显式输出唯一会话 key，群名仅展示。新群先有创建者，后续邀请按顺序加入成员。
- 引用是消息字段，仍使用内容快照；转发仍是内容。第一版移除撤回。
- 后台规则保留既有会话/好友私聊候选门槛。主动规则目标消息窗口 64、关联 32；后台规则 32。退群保留为后续扩展，不进入本版协议。

## 分工与验证

- 当前 Agent：设计、实现、定向验证、文档收口。没有独立 Agent 角色。
- 验收：申请、拒绝、再申请、通过、聊天；违规私聊和群邀请原子拒绝；NPC 建群、邀请、群内聊天；领取和转账处理同时产生操作提示与卡片状态；引用、转发与待发送确认；两份规则上下文和初始化数据与新契约一致。
- 最小验证：微信定向脚本、webpack 开发构建、修改文件静态检查、规则与 JSON 格式检查。宿主内生成效果仍需实机联调。
