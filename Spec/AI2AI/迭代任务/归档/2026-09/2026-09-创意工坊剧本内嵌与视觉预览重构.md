# 2026-09 创意工坊剧本内嵌与视觉预览重构

## 状态

自动化验收完成待宿主验收

## 目标与范围

- 修复角色语料在移动端被卡片、编辑控件或无空格长文本撑出横向滚动的问题，并覆盖只读与编辑两条展示路径。
- 统一角色选择器的信息架构：按 `type + key` 聚合角色身份，在身份下展示多个版本，最终仍只允许选择一个版本。
- 重构剧本编排工作台，使剧本身份、视觉方案、阵容、初始世界、开场文本、主线、任务和事件在同一剧本上下文中直接编辑。
- 将初始世界、开场文本、主线、任务和事件从独立资产注册表改为剧本内嵌数据，成为剧本对象的一部分和唯一权威来源。
- 建立共享剧本视觉方案注册表，首批提供灯、铸、刃、冬、心、杯、蛾、启、破镜九套成套主题与图标，并在工坊展示真实效果预览。
- 为 user、主要角色和次要角色统一提供角色主题色的真实对话框预览与运行时效果。
- 收敛特殊对话框的角色识别规则，支持酒馆当前用户名，同时移除名称检索词和模糊包含匹配造成的错误归属。

## 关键设计决定

### 剧本内嵌模型

- 初始世界、开场文本、主线、任务和事件不再拥有独立 UUID、注册表、引用选择器或跨剧本共享语义，直接随剧本保存、复制、导入和导出。
- 角色继续作为独立版本化资产；剧本只保存选中角色版本的 UUID。角色身份按 `type + key` 聚合，同一身份在一个剧本中只能选择一个版本，所有 user 版本继续互斥。
- 地图、世界经济、季节与节日、势力和种族继续作为全局共享资源；地图仍是项目唯一完整嵌套地图，其他全局资源仍按既有自动装配规则进入运行态。
- 项目尚未上线，不实现旧分离格式迁移、双读、双写或版本判断。当前内置数据、测试夹具和样例直接改为新格式。
- 组装器直接从剧本对象读取内嵌内容，不得把新模型重新转换成旧注册表或旧 UUID 引用后再走原组装链。

### 剧本编辑与视觉方案

- 剧本编辑器是内嵌叙事内容的唯一正式编辑入口；不再显示“选择已有开场/主线/任务/事件”等素材选择器。
- 剧本工作台复用现有领域编辑组件和公共视觉基础，但不建立可编辑任意 JSON 的通用表单。
- 主题与图标作为一个不可拆分的视觉方案选择。普通作者只看到中文名称和真实剧本卡预览，不接触 CSS 类名、SVG path 或内部 key。
- 建立单一视觉方案注册表，统一提供方案标识、中文名称、主题 token、SVG 图标和展示元数据；创意工坊、开场设置和设置页共同消费，不能各自维护主题白名单或复制样式事实。
- 首批方案固定为灯、铸、刃、冬、心、杯、蛾、启和破镜。无效方案在编辑与校验阶段显式报告，不依赖运行时静默回退。

### 角色选择与对话呈现

- 角色选择采用“角色身份 → 具体版本”的二级模型；选择新版本只替换当前剧本中的引用，不删除角色资产或影响其他剧本。
- user、主要角色和次要角色均保留 `meta.color`，均能在工坊看到使用实际头像、角色名称和示例台词的特殊对话框预览。
- 预览与运行时共享同一角色气泡呈现组件或共享呈现层，不维护近似 CSS 副本。
- 对话说话人按 `user → 主要角色 → 次要角色` 的类型优先级自动解析。
- user 精确匹配字面量 `user`、`substitudeMacros('{{user}}')` 返回的酒馆当前用户名，以及 user 自身姓名或 key。
- 主要角色和次要角色只精确匹配姓名或 key；不得使用 `名称检索词`，也不得使用 `rawName.includes(...)` 一类模糊包含匹配。

### 移动端边界

- 语料场景名、语句、摘要、按钮区和原位编辑控件必须在可用宽度内收缩或换行，不得产生工作区级横向滚动。
- 移动端继续使用与桌面相同的信息架构，但复杂剧本模块和版本详情以全屏分步区域承载，不将桌面多栏机械堆叠。

## 验收标准

- 主要角色语料在移动窄屏下可查看、新增、编辑、复制、排序和删除；超长无空格场景名及语句不会撑出横向滚动。
- 角色选择器首先聚合同 `type + key` 的身份，再展示各版本的作者、素材说明、引用摘要和差异；确认后每个身份最多保留一个 UUID。
- 剧本工作台可直接完成初始世界、开场文本、主线、任务和事件的创建、修改、排序与删除，全流程不出现叙事素材 UUID 或已有素材选择器。
- 新建、复制、保存、重读、导入、导出和组装剧本后，全部内嵌叙事内容保持字段类型、层级、顺序和语义。
- 世界书加载、保存和运行时组装不再要求 `<世界>配置`、`<开场文本>配置`、`<主线>配置`、`<任务>配置`、`<事件>配置`。
- 资产包不再单独导出上述五类剧本私有素材，也不存在它们的引用依赖闭包或 UUID 重映射。
- 工坊可在九套视觉方案间选择，并显示与开场设置页一致的主题、图标和剧本卡效果；设置页显示同一方案，不存在三处白名单分叉。
- user、主要角色和次要角色的颜色修改都能立即反映在真实对话框预览，并在运行时相同组件中生效。
- `【user】` 和 `【酒馆当前用户名】` 均使用 user 的头像与颜色；发生跨类型同名时按 user、主要角色、次要角色依次选择。
- 名称检索词中的别名或 `$all` 不会触发角色气泡；姓名或 key 的子串不会被误识别，只有精确匹配生效。
- 保存审阅仍能定位剧本内嵌字段和角色视觉元数据的实际变化；保存失败保持全有或全无。
