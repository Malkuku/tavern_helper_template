# 2026-09 创意工坊可编辑视觉组件重构

## 状态

自动化验收完成待宿主验收

## 目标与范围

- 将角色档案从“展示组件中铺设后台表单”重构为可直接操作的视觉档案。
- 技能、术、特殊状态、物品、关系、基础状态等内容首先以完成品形态呈现，在同一组件内完成原位编辑。
- 改善草稿变更的可见性；删除无行动价值的常驻自动装配统计，收敛“保存与发布检查”的命名和职责。
- 保持现有角色数据结构、角色类型差异、派生只读字段、引用规则、差异审阅和原子保存契约不变。
- 本轮不引入 JSON 编辑模式、固定属性栏、覆盖式抽屉、弹窗编辑器或独立聚焦编辑页。

## 关键设计决定

- 正式交互采用“真正的可编辑视觉组件”：查看与编辑共享同一视觉对象，不把完整表单作为默认外观。
- 文本、数值和枚举在对象被选中或具体字段获得焦点时显示编辑 affordance；非活动对象保持成品展示。
- 集合级新增、复制、删除和排序属于卡片动作，避免将动作与字段混成纵向表单。
- 编辑继续实时写入现有内存草稿；只有统一保存动作持久化，不增加组件级应用/取消状态。
- 桌面与移动端使用同一信息结构；移动端允许单列，但不得产生横向滚动或依赖常驻侧栏。

## Agent 分工

- 主 Agent：任务定界、视觉方案、正式实现、实现自测、Spec 与状态收口。
- 独立验收 Agent：从本任务验收标准检查静态结构、关键交互、构建和现有数据契约回归，不参与实现。

## 验收标准

- 默认状态下，角色的技能、术、特殊状态、物品、关系和生命状态看起来是可阅读的成品档案，而不是输入框集合。
- 选中对象后可在原位置完成契约支持的新增、编辑和删除；技能、状态、术、语料及物品等允许重复语义的集合提供复制，依赖顺序的集合提供手动排序。关系以目标身份为唯一键，不提供会制造重复目标的复制；不打开右侧检查器、弹窗或独立编辑页。
- 编辑控件不无意义横向拉满；长文本有清晰层级，卡片内部不出现嵌套滚动条争抢。
- 基础数值与生命最大值保持只读；工坊资产中的生命、体力、精神当前值固定同步对应最大值，不提供独立编辑，并与技能、术合并在同一档案分区。
- 不提供 JSON 编辑入口；所有修改仍进入同一草稿、差异审阅和原子保存流程。
- 未保存状态能至少定位到当前角色的具体档案分区；保存审阅继续展示资产级和字段级差异。
- 自动装配数量不再占据常驻检查区域；检查区域只呈现保存状态和真实、可行动的问题。
- 现有角色 fixture 读写往返、类型转换、引用关系和构建验证通过。
