# 阶段变化弹窗与弹窗测试

状态：实现与本地定向验证完成；待宿主触屏、MVU 与弹窗时序联调。

## 目标与范围

- 同一聊天中角色人设阶段等级发生变化时，手机顶部逐条提示角色、阶段、旧等级与新等级；点击进入观测。
- 设置页提供“测试全部弹窗”，依次预览 Weline 消息、组织任务、创伤稳定度警告、三类阶段等级变化及任务、技能、道具刷新成功。
- 预览只使用临时界面数据，不更改楼层、脚本变量、已读状态或正式通知历史。

## 关键设计决定

- 手机 Store 在变量刷新边界比较同一聊天的等级快照，覆盖自动结算和其他合法写入；首次读取及切换聊天只建立基线。
- 阶段变化以独立内存队列暂存；现有顶部通知组件负责呈现，关闭后消费一条。多级变化用起止等级一条提示。
- 测试入口由设置页发事件给手机壳层；预览优先于真实通知，完成后恢复真实通知显示。
- 任务候选及技能、道具货架只有在生成结果校验并成功写回后才追加刷新成功提示；失败与取消不提示。提示点击进入对应任务页或商店分类。
- 不改变现有任务与稳定度通知的持久化去重规则。

## 验收与验证

- 主要角色三项及次要角色恶堕度的升降级按实际变化提示；经验变化但等级不变、初次读取、聊天切换不提示。
- 同次多个变化逐条可见；关闭或点击后进入下一条，点击观测定位正确角色。
- 设置中的预览涵盖现有顶部弹窗类型和新增阶段类型，且不改业务数据或正式通知展示记录。
- 三类刷新成功各出现一条提示；失败、取消和仅发起生成均不出现，技能与道具提示点击后打开对应商店。
- 定向测试等级差分与队列；目标 ESLint、格式检查和开发构建；宿主触屏与真实 MVU 时序待联调。

## 分工与文档

单 Agent 实施与本地验收。更新人设阶段、手机应用提醒与设置相关长期契约。无旧机制取缔项。

## 完成记录

- Store 按聊天保存等级快照，对主要角色三项与次要角色恶堕度生成逐条提示；手机开闭状态均可展示，Weline 消息优先。点击提示可定位角色观测，同一角色的连续提示会重置到概览。
- 设置页新增“测试全部弹窗”，依次展示 Weline、任务、低稳定度和三类等级变化的真实通知组件；关闭或点击预览进入下一条，离开设置即清空预览，不写业务数据与通知历史。
- 任务、技能商店、道具商店的刷新成功提示接入成功写回点，并纳入预览序列；临时通知按实际成功顺序排队。
- 刷新提示扩展后，阶段通知、手机应用通知、任务正文结果、技能商店与道具商店定向脚本通过；目标 ESLint、Prettier、Webpack 开发构建及 `git diff --check` 通过。`validate-quests.cts` 因现有生成规则文本缺少其断言中的“禁止全部集中于一个角色”而失败，本轮未修改该生成规则或测试。
- `validate-stage-notifications.cts`、`validate-phone-notifications.cts`、目标 ESLint、Prettier、Webpack 开发构建及 `git diff --check` 通过。真实宿主的 MVU 事件时序、触屏视觉与弹窗队列仍待联调。
