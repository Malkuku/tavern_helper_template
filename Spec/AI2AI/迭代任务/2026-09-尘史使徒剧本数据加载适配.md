## 状态

## 目标与范围

- 为尘史使徒的解构式剧本数据建立独立的“创意工坊”入口与加载适配。
- 以开场白的 `内容配置` UUID 清单为入口，从分类资源注册表组装运行时 `stat_data` 和开场文本。

- 独立入口预定为 `src/创意工坊/index.ts`；当前 Webpack 会自动发现该入口并输出 `dist/创意工坊/index.js`，无需新增手工入口配置。

## 关键设计决定

### 已确认事实

- 事实参考限定为 `O:\St Working` 的提交 `8605da8`、`3fd2211`、`24fadec`，以及 `O:\St Working\角色卡开发\尘史使徒\尘史使徒Beta\配置` 当前数据。
- `开场白.json` 包含固定数据与 5 个开场白；每个开场白通过 `内容配置` 引用分类资源 UUID。
- `世界`、`主线`、`开场文本` 是单例引用；`世界经济`、`季节与节日`、`势力`、`种族`、`任务`、`事件` 是集合引用。
- 普通集合资源由 UUID 定位条目，并以条目的 `key` 写入运行时分类对象。
- `角色` 条目必须按 `type` 分入 `user`、`主要角色`、`次要角色`，再以 `key` 定位；`user` 是单例。
- `地图` 条目使用 `root` 描述递归 UUID 拓扑，节点内容来自 `地图节点` 注册表，不能套用普通集合的 `entry.data` 规则。
- 空的 `任务.json` 和空引用数组应组装为空对象。
- `开场文本` 是宿主消息内容，不属于 `stat_data`。
- 最终 `stat_data` 结构以 Beta 的 `MvuZod.js` 与仓库 `src/尘史使徒/UI/types/StatData.d.ts` 的交集为基准；两者差异须在实现前明确处理，不能只依赖 Webpack 的 `transpileOnly` 构建。
- 无效 UUID、重复 `key`、未知角色 `type`、重复 `user` 和地图节点缺失均不得静默跳过。

### 用户已确认的第一版边界

- 第一版提供查看、选择、组装、应用和 JSON 导出，不提供资源增删改或持久化编辑。
- SillyTavern 当前角色主世界书中的分类配置条目是运行时数据源；本地 JSON 仅用于测试，不做双向同步。
- 应用时同时写入最新消息楼层的 `stat_data` 并将该楼层正文替换为开场文本。
- UI 展示作者；`可用: false` 的开场白禁用；`自定义主角` 作为后续人物设置标记；错误展示资源分类和 UUID。
- 新组装器直接取代旧式 `<VariableInsert>` 整体加载职责，不保留第二条兼容路径。

### 失败策略

- 组装采用全有或全无语义：发现契约错误时返回结构化错误，不产生部分 `stat_data`，也不执行宿主写入。
- 错误至少包含资源分类、引用 UUID、错误类型和可读说明；UI 只负责呈现，不重新解释或修复数据。
- UI 展示分类、UUID 与具体错误说明。
