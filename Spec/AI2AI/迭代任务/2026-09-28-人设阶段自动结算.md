# 人设阶段自动结算

## 状态

实现与定向验证完成；待酒馆宿主 MVU 时序联调。

## 目标与范围

在手机脚本内根据每轮规则已写入的 `累计经验`
自动结算主要角色的创伤稳定度、好感度、恶堕度及次要角色的恶堕度。规则只写经验；脚本按[人设阶段经验与等级](../API/人设阶段经验与等级.md)的公式逐级扣除需求、更新等级，允许负经验与一次多级变化。恶堕等级不可下降。

## 关键设计决定

- 统一纯结算逻辑是三项经验曲线的唯一实现；从角色自己的描述等级键取得可用范围。
- 在现有手机 Store 的 MVU 变化入口检测并写回，不给各应用分别实现等级计算。写回沿用当前楼层 `stat_data`
  与 Store 顺序队列；结算结果不变时不重复写入。
- 聊天切换时取消待处理旧聊天写入；异常阶段数据显式报告，不覆盖原数据。
- 本轮新增结算机制，没有需要取缔的旧等级自动结算路径。

## Agent 分工

单 Agent 完成纯结算、Store 接入、定向验证和文档收口。

## 验收标准

- 三项公式与已定 0～5 稳定度边界需求一致，并能处理负等级及 6 级以上。
- 正负经验保留、逐级扣经验和一轮跨多级正确；恶堕等级在负经验时保持原等级。
- 主要角色和次要角色都结算；没有经验变化时不写回；旧存档次要角色缺恶堕度时正常读取。
- 结算写在最新聊天楼层，重复 MVU 事件不造成重复升级；切换聊天后不写旧聊天。
- 宿主未提供的运行时验证明确记录，不将本地静态结果冒充宿主验收。

## 测试所有权与验证范围

单 Agent 使用定向 Node 断言验证三条曲线、跨级、负值、边界与角色容器；执行目标文件 ESLint、Prettier 和开发构建。宿主内用实际 MVU 事件、聊天切换和楼层写回联调。
