# 统一角色观测与初始接触资料

状态：实现与定向验证完成；待酒馆宿主触屏、图片与 MVU 时序联调。

## 目标与范围

- 将组织 App 的心象监测和人物观测合并为一个角色观测入口、一个已发现角色选择器和同一组概览、身体、档案分页。
- 保留主要与次要角色各自的数据字段、图片、经验阶段和解锁规则；页面依角色类型展示相应内容。
- 依据当前角色资源中的四位初始目标人设，补足轮播可见线索、角色对应的接触任务和实际可用的初始道具。

## 关键设计决定

- 角色选择顺序跟随
  `系统.已发现目标`；只展示名单中的运行态角色。角色类型与 key 共同确定选择项；已发现但尚无运行态档案的首选目标显示待建立状态。
- 三个分页统一命名为“概览 / 身体 / 档案”。主要角色概览显示三项阶段，次要角色概览显示公开基础资料和可选恶堕度；身体和档案页继续按各自字段展示。
- 图片只用于有已登记角色图的目标；没有图片的次要角色使用紧凑资料头。首位目标选择仍在空发现名单时出现，选择成功后跳转任务页。
- 四位首选目标的可见线索只采用当前角色资源可核实的身份与行动特点，避免提前展示付费档案和核心创伤。每人发放一件与接触方式相符的普通 D 级道具，不引入未实现的自动效果；任务名称、5 点奖励和一次性发放机制沿用既有契约。
- 相同名称道具只有规格一致时合并；发放失败不得留下部分变量变更或正文记录。

## 分工与验收

- 当前 Agent：设计、实现、定向行为验证和文档收口；不设独立验收角色。
- 观测区只出现一个入口；主要、次要和待建立档案角色在同一选择列表中切换，分页不出现空白或错误内容。
- 初始轮播四人的身份线索、任务与道具分别对应资源设定；隐藏角色不出现，重复选择不重复发放，道具冲突时整体失败。
- 已有解锁记录、恶堕图等级限制、经验进度与图片缓存行为保持有效。
