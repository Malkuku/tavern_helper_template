# 已发现目标可见性

状态：实现与定向验证完成；待宿主变量规则与界面联调。

## 目标与范围

魔法少女变量新增 `系统.已发现目标: string[]`。数组按主要或次要角色在 `角色` 字典中的实际 key 精确匹配；只有列表中的角色在面向玩家的前端入口显示，`user` 始终显示。初始值为空数组，隐藏开局预置但剧情尚未发现的角色。

## 关键设计

- 变量保留完整角色数据；仅在展示边界过滤。剧情规则与世界书 `角色列表` 仍可读取角色，供后续叙事使用。
- 手机人物观测、心象监测、微信角色账号及会话、附近的人、手机角色编辑器的角色列表均遵守同一发现判定。微信群聊若包含未发现角色则整段会话暂不展示，避免成员或消息泄露。
- `已发现目标` 由独立变量规则维护；前端收录或手动加入角色时只写角色档案，不自动改变发现名单。新人物收录页的候选卡片来自当前正文生成结果，属于收录操作本身，不受已发现名单过滤。
- 缺少字段的旧楼层按空列表处理，不自行推断已发现角色。无模糊匹配；旧数据与新字段均不重写角色资源。

## 验收与验证

- 空列表不展示主要/次要角色；写入 key 后相应入口显示，移除后重新隐藏；`user` 始终可见。
- 微信联系人、会话、名片候选、附近的人和手机角色编辑器不泄露隐藏角色；包含隐藏成员的群聊不显示。
- 收录和手动加入角色不会改写发现名单；变量规则写入 key 后前端随变量更新显示。旧楼层缺字段不会报错。
- 定向脚本验证数据组装、发现判定与运行态加入；目标静态检查和开发构建。
