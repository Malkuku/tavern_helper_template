# Weline 具名表情库

## 状态

实现与本地验证完成；待 SillyTavern 宿主触屏、脚本变量与旧聊天显示联调。

## 目标与范围

表情图片引入库时填写唯一名称；账号从库中选择名称作为可用表情，聊天发送继续使用 `<表情包>名称</表情包>`。管理页区分共享表情库与当前账号已选表情。

## 关键设计决定

- 脚本变量 `magicGirlWeChatStickerLibrary` 保存名称到图片引用的映射；图片内容仍由现有 Weline 图片库存储。名称在库内唯一，不允许空名或覆盖同名项。
- 新的账号表情映射继续遵守既有 `Record<名称, 字符串>` 存档结构，但值采用 `sticker://名称` 引用；名称选择来自共享库。这样无需改变世界书、正文标签或旧存档结构。
- 旧账号中的图片 URL 只作历史兼容读取；新表情只能从具名库选入账号。旧同名不同图仍按发送者账号的旧图片优先显示，避免迁移改写历史消息。
- 管理页允许从文件、图片库或外部 URL 为共享库引入具名表情；账号可选入、移除库中的表情。聊天面板上传时为库中图片命名并选入 user 账号。
- 图片库清理需要识别共享表情库中的图片引用。

## Agent 分工

- 当前 Agent：设计、实现、定向验证、Spec 收口。无独立测试 Agent。

## 验收标准

- 引入图片时即填写名称，同名不会覆盖原图片；入库后所有账号可按该名称选用。
- 账号选入的名称显示在聊天表情面板，发送值与库名一致；移除账号引用不删除共享图片。
- 旧表情仍能发送和显示；图片库不会清理仍被具名表情库引用的图片。
- 失败时展示原因，用户的选图和命名草稿保留。

## 测试所有权与验证范围

- 当前 Agent：具名库读写、重复名称、账号引用、旧图片兼容和图片清理定向测试；ESLint、Prettier 与手机构建。
- 宿主：触屏、脚本变量持久化及旧聊天实际显示。

## 文档更新项

- 更新 Weline 设计、微信交互 API 与索引；旧 per-account 写入描述改为库引用。

## 旧机制取缔项

- 新表情不再把各账号独立图片 URL 当成创建表情的主路径；旧 URL 仅保留历史读取职责。

已新增共享具名表情库、`sticker://名称` 账号引用与管理页的“已选表情 / 表情库 / 引入”流程。聊天面板上传和图片库选图也走具名入库；旧账号 URL 与原 `<表情包>` 消息继续读取。图片库清理会保护共享库引用。全局库不提供删除入口，避免跨聊天账号仍引用时误删图片。
