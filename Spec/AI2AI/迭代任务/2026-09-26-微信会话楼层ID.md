# 微信会话楼层 ID

## 目标与范围

每个微信会话的消息和操作共用从 1 开始的连续楼层 ID。正文增量、UI 操作与微信变量使用同一身份；引用和款项目标按 ID 定位。同步根据会话内 ID 判断已应用与新增事件，不再使用聊天变量日志签名。

范围包括手机类型、Store、正文解析和应用、界面交互、初始化校验、唯一开局配置、主动及后台两份规则、定向验证与 API Spec。

## 关键决定

- ID 是会话内序号，等于当前 `消息.length + 1`；消息和操作均占一个序号。
- 同一 ID 的事件与已存事件一致时视为重放；内容不同时报冲突；新 ID 必须紧接会话末尾。
- 新协议由两份规则输出 ID；旧聊天数据在首次处理时按现有数组顺序补齐 ID，不改消息顺序。
- `准备发送` 记录预期 ID，正文首条新 user 消息必须匹配该 ID 与内容。
- 引用快照保留显示内容并带原消息 ID；款项操作目标使用原消息 ID 和内容下标。

## 分工与验收

当前 Agent 实现并进行定向验证。验收连续发送、重复/改写事件、重复同文消息、跨会话 ID、引用与多项款项定位，以及删楼层后的变量回滚路径。修改对应长期 Spec 和两份规则。

## 旧机制取缔项

- 移除聊天变量 `magicGirlWeChatAppliedLogs` 的读取和写入。
- 移除以发送者和时间猜测款项目标、以内容快照充当唯一引用身份的定位职责。
