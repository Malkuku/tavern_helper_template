# 生成结果容错

## 状态

实现与定向验证完成；宿主生成时序和视觉待联调

## 目标与范围

降低手机组织任务、技能和道具商店因生成文本的小瑕疵而整次失败的频率。处理同楼旧标签、额外字段、可由系统确定的任务初始状态、可回退的图标、与交易无关的技能升级贡献限制。结算和数据安全校验继续生效。

## 关键设计决定

- 只消费本次最新的完整生成标签；旧标签可以留在同一楼层，但不能重用旧结果结算。
- 生成项的额外字段忽略，不写入变量。候选任务的进度与完成标记由手机统一设置。
- 技能同名新版本允许贡献持平或下降；购买后按实际持有技能重算角色评级，玩家自行判断效果与价格是否合适。
- 图标缺失、形状不合要求或不安全时使用界面默认图标，不把原始 SVG 写入变量。
- 本轮保持任务、技能和道具生成的目标数量与交易门槛；若需改变刷新数量和报价关系，另行确定产品规则。

## Agent 分工

- 当前 Agent：实现、定向验证和文档收口；不设子 Agent。

## 验收标准

- 同楼旧标签与新完整标签并存时，以本次新标签结算；旧标签本身不触发重复结算。
- 额外字段及候选任务初始状态写法差异不阻断刷新，写入结果仍符合正式数据模型。
- 技能贡献持平或下降的同名版本可出现在货架并购买，角色评级按实际总贡献更新。
- 无效 SVG 不进入变量或 DOM；余额不足、无效金额、任务奖励、缺失必要字段与交易冲突仍明确失败且不部分写入。

## 验证范围

- 定向脚本覆盖生成解析、技能购买、旧标签与失败路径；目标 ESLint、Prettier、构建及 diff 检查。

## 文档更新项

- 更新组织任务、技能商店和道具商店的生成结果契约，删除失效的严格校验描述。
