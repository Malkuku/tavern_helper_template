# 创意工坊正式构建

## 状态

自动化验收完成待宿主验收

## 目标与范围

- 将现有剧本读取预览页重构为可日常使用的资产创作与分发插件。
- 在同一插件入口内提供彼此隔离的用户工作区和开发者工作区。
- 用户侧提供当前主世界书资产包导入导出，以及从现有角色资产向当前运行剧本加入角色。
- 开发者侧提供十二类资产的专用编辑器、剧本引用编排、引用检查、草稿、差异预览和显式保存。
- 所有资产编辑与资产包安装最终持久化到当前角色主世界书。

## 关键设计决定

- 当前角色主世界书是唯一资产来源和持久化目标，不扫描其他世界书。
- 用户侧与开发者侧共享资产仓库、Schema、引用图、包格式和世界书事务服务。
- 编辑采用内存草稿，字段变化不自动写回；保存前校验并原子写回。
- 剧本允许以临时不完整状态保存，但必须强制 `可用: false`；可玩性由 UUID 引用能否完整解析动态计算。
- 删除被引用资产时默认展示影响；强制删除会同步移除引用。集合引用删除对应 UUID，地图节点删除对应拓扑节点，必填剧本引用被清除后剧本自动禁用。
- 资产包是版本化单一 JSON 文件，可包含开发者选择的任意分类资产；不包含二进制媒体，不保存可玩性布尔标记。
- 导出剧本时默认选择引用闭包，但允许开发者裁剪；完整性由导出或导入目标环境实时检查。
- 导入按 UUID 合并：新增、相同跳过、不同内容由用户选择覆盖、跳过或复制。复制生成新 UUID 并重写包内引用。
- 资产包导入在预检和冲突决策完成后原子写入，失败自动回滚，不建立持久化快照或成功写入撤销历史。
- 运行时角色加入只复制当前主世界书中的角色资产到当前 `stat_data.角色`；不回写世界书、不修改 `system.关注角色列表`。目标 `type + key` 已存在时提示用户确认完整覆盖。
- 创意工坊不创建聊天或初始化剧本；尘史模块从主世界书发现剧本并负责开局。

## Agent 分工

- 主 Agent：契约、模块设计、实现、实现自测、文档收口。
- 独立验收：主要实现完成后另行执行，从本任务验收标准独立推导用例。

## 验收标准

- 单一工坊入口可在用户工作区与开发者工作区间切换，默认展示用户工作区。
- 页面具有稳定的模块化布局，在宿主可用宽度内无横向溢出，核心保存、导入、导出和冲突动作可见。
- 十二类资源均有契约对应的专用编辑界面，不以裸 JSON 编辑器作为正式编辑入口。
- 开发者可创建、复制、编辑、删除资产；修改先进入草稿，显式保存后才写入主世界书。
- 保存前显示差异与引用问题；失败不产生部分世界书修改。
- 不完整剧本能保存但被强制禁用；尘史模块仍可展示但不能启动。
- 可按选择范围导出版本化 JSON 资产包，并能计算包自身的缺失引用。
- 导入能计算“包内 + 当前世界书”的引用完整性，并正确处理 UUID 新增、相同、覆盖、跳过和复制重映射。
- 用户可从当前主世界书选择主要或次要角色加入当前运行剧本；冲突覆盖需明确确认，关注列表保持不变。
- 工坊 UI 不再提供运行态剧本 JSON 导出或“应用到当前聊天”。

## 测试所有权与验证范围

- 实现自测：资产仓库解析/序列化、编辑态与可玩态校验、引用图、级联删除、包导入导出、UUID 重映射及角色运行态写入的定向测试。
- 前端验证：相关 ESLint、TypeScript 和 Webpack 构建；检查模块边界与响应式状态。
- 独立验收：从验收标准覆盖成功、取消、冲突、损坏包、缺失引用、写入失败回滚和角色覆盖路径。
- 宿主人工验收：真实 SillyTavern 中验证世界书持久化、资产包下载/上传、MVU 角色写入和浮层卸载。
