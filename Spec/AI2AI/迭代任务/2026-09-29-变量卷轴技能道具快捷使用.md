# 变量卷轴技能道具快捷使用

## 状态

实现与本地验证完成；待宿主视觉联调

## 目标与范围

- 在「命运分歧」悬浮窗显示当前楼层 `角色.user` 持有的技能和随身道具，并提供快捷使用入口。
- 沿用手机页面的持有技能、道具图标和卡片视觉，手机页与卷轴共用权威组件；遵循[视觉复用与参考保真规则](../视觉复用与参考保真规则.md)。
- 点击使用仅向酒馆聊天输入框追加含名称与效果的使用意图；道具可指定持有范围内的正整数数量。不自动发送，也不直接扣除技能、道具数量或耐久。
- 保留现有命运选项和变量日志行为；仓库物品不作为随身快捷使用项。

## 关键设计决定

- 变量卷轴独立读取当前楼层 `stat_data.角色.user`，不依赖手机 Store 的运行实例；聊天和变量事件触发刷新。
- 技能与道具分别成为悬浮窗页签，点击卡片可展开完整描述、作用及使用操作。
- `OwnedAssetCard` 负责持有条目的图标、标题、评级/数量、描述、作用、道具元数据及评级光效；操作区由入口提供。`InventoryIcon` 自带图标底纹与安全 SVG 样式。
- 提交时重新读取当前楼层持有数据并校验，避免聊天切换或库存变化后写入过期意图。输入框保留未发送草稿。

## Agent 分工

- 当前 Agent：设计、实现、自测与文档收口。本任务不设独立测试 Agent。

## 验收标准

- 当前楼层的技能和随身道具可在对应页签查看，数量与效果跟随变量刷新；无数据时显示空状态。
- 技能使用和道具使用均向输入框追加意图并触发 `input` 事件，道具使用数量受当前库存约束。
- 聊天或楼层切换后旧数据不残留；失去持有、数量不合法或缺少输入框时显示错误且不写入草稿。
- 命运选项、变量日志、拖动及缩放继续工作。
- 手机持有技能、随身物品与卷轴直接渲染同一组件；同一数据的图标、卡片、评级效果和展开层级一致，小窗内不产生横向溢出。

## 测试所有权与验证范围

- 实现自测：定向覆盖技能、道具、空数据及无效数量，静态检查与 Webpack 构建。
- 视觉复用检查：三个入口导入同一卡片组件；旧图标与持有条目 CSS 不再由手机全局样式重复维护。
- 宿主联调：在 SillyTavern 检查变量事件时序、触屏操作和输入框写入。
