# 技术选型与总体架构

## 技术栈

- TypeScript 与 Vue 3 负责界面及交互逻辑，Pinia 管理响应式状态。
- Webpack 根据 `src/**/index.{ts,tsx,js,jsx}` 自动发现入口，并折叠已被父入口包含的嵌套入口。
- Tavern Helper、SillyTavern 和 MVU 通过仓库根部 `@types` 声明的全局接口提供宿主能力。
- jQuery 用于 iframe 加载时机、宿主 DOM 与样式传送；业务界面优先使用 Vue。

## 运行模型

顶层 `src/<区域>/index.ts` 是部署单元。带 `index.html` 的部署单元直接挂载到自身
`#app`；不带 HTML 的脚本入口可将 Vue 浮层挂载到宿主页面，并在 `pagehide` 时释放实例、样式和 Tavern Helper 事件。

## 模块分区

- 独立展示与生成界面：`图片展示`、`开场白`、`战斗日志`、`敌人生成`、`角色生成`、`音乐播放`。
- 独立脚本浮层：`创意工坊`
  在同一入口提供用户与开发者工作区，正式创作界面聚焦角色和叙事剧本；共享世界资源由底层自动装配，开发者资产包保留兼容导入导出职责；运行时支持加入主要/次要角色及整体覆盖
  `user`。`地图查看器` 通过脚本按钮开关只读地图浮层，直接读取当前消息楼层的运行时地图。
- `手机界面` 是独立脚本浮层，复用 `startFloatingUi`
  挂载。SVG 悬浮入口可拖拽；移动端覆盖视口，桌面端通过屏幕上方的十字手柄拖拽手机尺寸窗口，窗口外可继续操作宿主页面。底部白条独占导航空间，是返回桌面的统一入口，在桌面点击则退出手机；应用内部上一层导航仍由各应用处理。控制中心不另设退出按钮，其开关和滑杆仅维护本地演示状态。微信由独立组件提供四标签、会话列表、会话详情和基于变量的发送流程。组织任务、角色观测、商店、我的档案、已拥有技能及随身物品统一从手机桌面的“魔女恶堕计划”进入；`apps/witch/WitchApp.vue`
  负责五栏导航和任务首页，领域组件继续消费同一魔法少女 Store。已保存桌面布局在读取时过滤旧组织图标并补入新 App 图标。心象与人物档案支持积分解锁，我的档案支持基础信息编辑，物品管理可切换随身与仓库库存。地图应用读取当前楼层的嵌套地图，复用尘史地图坐标与避让算法，在手机浅色视图中只读展示彩色 SVG 节点、层级和详情。其他轻量应用提供备忘录、照片、短信草稿等脚本变量功能及天气等世界状态展示。
- 手机桌面的“连接诊断”应用检查酒馆宿主接口、提示词模板扩展的固定无副作用 EJS 执行、以及图片 URL 的浏览器实际加载。三项结果独立展示；图床检查仅证明图片读取可用，不代表上传能力。测试图片默认使用项目现有资源，用户输入的地址保存在手机脚本变量中。首次完整检查前，桌面、Dock 或文件夹里的应用图标沿用桌面统一红点提醒；完整检查结束后将已检查状态保存为脚本变量，检查结果是否成功不影响红点清除。
- `手机界面/types.ts` 保存本卡的 `stat_data` 契约，`手机界面/store/StatStore.ts` 保存独立 Pinia
  Store。手机入口初始化 Store；它从当前消息楼层读取变量，监听 MVU 更新与聊天变化，并通过 `MvuUtil`
  写回。Store 处理微信发送缓冲、`Chat_On_WeChat` 事件、assistant 正文中的 `<WeChatLog>`
  增量，以及组织技能商店的手动生成、校验和结算。`App.vue` 负责浮层、拖拽与手机应用切换，桌面和控制中心位于
  `components/`，微信、组织 App 与其他领域视图位于 `apps/`。组织 App 的品牌及各业务页样式统一由 `apps/witch/witch.css`
  维护，手机与微信样式仍位于 `styles/`。
- 手机主要角色以 `Record<string, 角色人设>` 保存和读取，档案页遍历实际键；角色名称和数量不在前端固定。
- 手机档案解锁记录保存在当前聊天楼层的 `stat_data.手机.档案解锁`
  可选字段中，和恶堕积分扣减同次写回；资料编辑、解锁与微信写入共享 Store 顺序队列。主要角色的人设阶段、身体状态只展示当前等级对应的描述。
- 手机 Store 在当前楼层 MVU 更新后，按统一的人设阶段曲线结算主要角色三项阶段和次要角色恶堕度。对话规则只写有符号的经验余额，脚本逐级扣经验并写回等级；恶堕等级不会下降。无变化不写回，结算与其他手机操作共用顺序队列。
- 当前楼层仅有 `stat_data.作者 = 987` 时，手机 Store 从主世界书的 `<配置>唯一开局`、`<配置>角色资源` 与
  `<配置>地图资源`
  JSON 按 UUID 引用组装当前楼层变量。脚本启动和聊天切换后每秒重试检查，直到当前聊天成功；切换时取消过期检查并清理视图。手机打开与关闭不控制初始化。成功且手机尚未打开时，悬浮入口以抖动和紫色粒子提示，点击后停止。`store/worldbookInit.ts`
  是新聊天组装的唯一规则实现，`store/initialDataSchema.ts` 对齐 `types.ts`
  校验完整结果；角色列表从运行变量提取人物资料供叙事使用。
- 手机桌面的排序、Dock 和文件夹以脚本变量 `magicGirlPhoneLayout` 持久化；`desktopLayout.ts`
  负责布局校验与移动规则，桌面组件负责指针交互，布局不进入剧情 `stat_data`。
- 微信未读位置以脚本变量 `magicGirlWeChatRead`
  按聊天 ID 和会话 key 保存；手机 Store 在微信数据刷新时识别新增他人消息与未读，`App.vue`
  根据手机开关状态展示手机内或宿主页面顶部的预览，微信界面负责会话已读与直达导航。
- `变量卷轴` 脚本以「命运分歧」为唯一悬浮入口，在宿主页面展示当前消息楼层的 `<op>...</op>` 命运选项、变量日志、`stat_data.角色.user` 持有的技能和随身道具，以及 `stat_data.任务` 中的已接任务。展开窗口内切换五页；手机端保持小窗并在内部滚动，不覆盖整个视口。选项、技能与道具使用意图、未完成已接任务的推进意图点击后追加到酒馆输入框，不主动发送或立即改写持有物与任务状态。旧楼层正则选项模板已退出，部署时需停用旧正则替换并启用 `dist/变量卷轴/index.js`。
- 手机持有技能、随身道具和变量卷轴的对应条目共用 `手机界面/apps/data/OwnedAssetCard.vue`；安全 SVG、默认图形与底纹由 `InventoryIcon.vue` 统一渲染。使用与库存操作由各入口提供卡片操作区。
- 手机任务页候选与已接任务、变量卷轴已接任务共用 `手机界面/apps/quests/QuestCard.vue`；卡片负责评级外观、目标、进度与奖励，手机 Store 独占接取、放弃和领奖写入。
- 核心角色卡应用：`尘史使徒`，包含路由、Pinia Store、地图、面板、角色、任务、商店、图书馆等子域。
- 共享能力：`src/util` 是模板级运行工具，`src/Utils` 是当前业务共享的消息、MVU 和世界书适配层，`src/Constants`
  保存跨模块事件名。

## 权威路径约束

- 由手机交互触发的 AI 内容生成，以脚本/宿主负责触发、计价、扣费、状态流转、结果校验与写回；AI 只负责生成约定内容。字段存放在
  `stat_data` 中不代表 AI 负责解释或更新该字段；给 AI 的上下文仅包含生成内容所需的信息。
- 为生成流程增加持久状态前，先核对已有字段、事件和串行写入是否足以表达所需事实。每个新增字段都要有无法从现有状态或流程得到的独立职责；不因担心重复处理而预设请求缓冲、结算标记，也不为避免 AI 看到字段而迁移存储位置。
- 生成规则优先写明输出数量、字段结构、完整语义和正向示例。覆盖式升级应同时示范已有版本与新版本，新版本效果必须能独立理解；模型无法执行的触发、扣费或变量写入指令不放进内容生成规则。确定性约束由脚本校验。
- 浮层挂载、样式传送与卸载生命周期应由一个共享运行模块负责；各入口只声明 App、插件和项目初始化。
- 变量标签与 JSON Patch 日志的解析应由一个共享解析模块负责；Vue 组件只负责响应状态和渲染。
- 真实宿主边界可以保留 adapter；无调用者、无动态注册且不属于构建入口的历史 helper 不作为兼容层保留。
- 各部署单元必须使用本区域 Store，不能跨区域依赖同名 Pinia Store。
- 尘史使徒剧本组装以 `src/创意工坊/scenario/assembler.ts`
  为唯一规则实现；创意工坊 UI、尘史使徒开场页和宿主写入层只能消费组装结果，不能各自解析分类资源。
- 顶层运行时状态不保存准则逐级能力表；`user` 与主要角色的 `术之等级`
  是等级、经验与派生数值的数据来源。次要角色及其中的敌人由 AI 动态生成，基础数值和生命状态以 AI 参考数值表后写入的结果为准，不由术之等级重算。面向玩家的准则介绍由角色面板前端静态维护，不从
  `stat_data` 读取，也不直接转录面向 AI 的完整准则设定。
- 创意工坊是无 `index.html` 的脚本入口，通过共享 `startFloatingUi` 挂载，构建产物为 `dist/创意工坊/index.js`。
- 创意工坊以 `assets/presentation.ts`
  统一负责固定资产默认值、业务标题摘要、字段级差异与安装预览等纯展示模型；工作区组件负责流程状态，各领域编辑组件只编辑已有契约字段。通用递归结构编辑器不属于正式创作路径。
- 地图以带资产包装的完整嵌套 `data`
  为权威表示；注册表允许多张地图，剧本以单个 UUID 显式绑定。正式代码不读取、迁移或保存旧地图节点注册表与 UUID 拓扑。
- 地图节点图标直接保存经过安全子集校验的完整 SVG；尘史运行时、工坊地图预览和剧本地点选择消费同一共享地图组件，不维护图标名称映射或近似预览。
- 独立地图查看器同样消费共享地图组件，以可选 `modern`
  主题改变视觉但不复制坐标、碰撞、缩放、搜索和安全 SVG 逻辑；默认主题保持尘史运行时视觉。
- 创意工坊不创建聊天或初始化剧本；尘史模块发现主世界书中的可用剧本并负责开局。
- 创意工坊外部 AI 角色协作以 `assets/roleGenerator.ts`
  负责角色规则与准则/术/物品静态设定读取、势力和种族运行态 JSON 投影、地图分层清洗投影、零上下文字段指南与访谈任务组装、工坊资产与单个
  `stat_data`
  角色 JSON 的边界转换及 Beta 角色结构校验。地图前三层保留创作设定，后续仅保留节点层级，全量删除图标、坐标与未知附加数据；种族仅作开放参考。经济和节日不进入角色任务。派生属性使用与
  `MvuZod.js` 同源的 `DOC/数值计算.ts` 重算，但仅适用于 `user`
  和主要角色；次要角色保留 AI 输入数值。Beta 角色筛选 EJS 将检索词中的 `$all` 解释为无条件匹配。
- 创意工坊在移动端以互斥面板组织目录、编辑器和检查信息，并使用单一内容滚动区与安全区操作栏；对话框留在宿主浮层挂载树中，避免 Vue
  Teleport 解析到后台脚本 iframe。

## 有意保留的现状

- 各区域 `MessageStore.getMessage()`
  在宿主返回空消息集合时会先清空当前消息，再继续读取首条消息。项目实际运行中未观察到该流程产生问题，因此当前按既有宿主契约保留，不进行预防性重构。只有出现可复现异常或宿主消息返回契约变化时再重新评估。
