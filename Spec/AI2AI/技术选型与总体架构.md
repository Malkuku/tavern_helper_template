# 技术选型与总体架构

## 技术栈

- TypeScript 与 Vue 3 负责界面及交互逻辑，Pinia 管理响应式状态。
- Webpack 根据 `src/**/index.{ts,tsx,js,jsx}` 自动发现入口，并折叠已被父入口包含的嵌套入口。
- Tavern Helper、SillyTavern 和 MVU 通过仓库根部 `@types` 声明的全局接口提供宿主能力。
- jQuery 用于 iframe 加载时机、宿主 DOM 与样式传送；业务界面优先使用 Vue。

## 运行模型

顶层 `src/<区域>/index.ts` 是部署单元。带 `index.html` 的部署单元直接挂载到自身 `#app`；不带 HTML 的脚本入口可将 Vue 浮层挂载到宿主页面，并在 `pagehide` 时释放实例、样式和 Tavern Helper 事件。

## 模块分区

- 独立展示与生成界面：`图片展示`、`开场白`、`战斗日志`、`敌人生成`、`角色生成`、`音乐播放`。
- 独立脚本浮层：`创意工坊`，在同一入口提供用户与开发者工作区，正式创作界面聚焦角色和叙事剧本；共享世界资源由底层自动装配，开发者资产包保留兼容导入导出职责；运行时支持加入主要/次要角色及整体覆盖 `user`。
- 变量与选项浮层：`变量卷轴`、`变量卷轴-蒸汽朋克`、`选项-蒸汽朋克`。
- 核心角色卡应用：`尘史使徒`，包含路由、Pinia Store、地图、面板、角色、任务、商店、图书馆等子域。
- 共享能力：`src/util` 是模板级运行工具，`src/Utils` 是当前业务共享的消息、MVU 和世界书适配层，`src/Constants` 保存跨模块事件名。

## 权威路径约束

- 浮层挂载、样式传送与卸载生命周期应由一个共享运行模块负责；各入口只声明 App、插件和项目初始化。
- 变量标签与 JSON Patch 日志的解析应由一个共享解析模块负责；Vue 组件只负责响应状态和渲染。
- 真实宿主边界可以保留 adapter；无调用者、无动态注册且不属于构建入口的历史 helper 不作为兼容层保留。
- 各部署单元必须使用本区域 Store，不能跨区域依赖同名 Pinia Store。
- 尘史使徒剧本组装以 `src/创意工坊/scenario/assembler.ts` 为唯一规则实现；创意工坊 UI、尘史使徒开场页和宿主写入层只能消费组装结果，不能各自解析分类资源。
- 创意工坊是无 `index.html` 的脚本入口，通过共享 `startFloatingUi` 挂载，构建产物为 `dist/创意工坊/index.js`。
- 创意工坊以 `assets/presentation.ts` 统一负责固定资产默认值、业务标题摘要、字段级差异与安装预览等纯展示模型；工作区组件负责流程状态，各领域编辑组件只编辑已有契约字段。通用递归结构编辑器不属于正式创作路径。
- 地图以单个带资产包装的完整嵌套 `data` 为唯一权威表示；正式代码不读取、迁移或保存旧地图节点注册表与 UUID 拓扑。
- 创意工坊不创建聊天或初始化剧本；尘史模块发现主世界书中的可用剧本并负责开局。

## 有意保留的现状

- 各区域 `MessageStore.getMessage()` 在宿主返回空消息集合时会先清空当前消息，再继续读取首条消息。项目实际运行中未观察到该流程产生问题，因此当前按既有宿主契约保留，不进行预防性重构。只有出现可复现异常或宿主消息返回契约变化时再重新评估。
