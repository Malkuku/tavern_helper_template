# 小说工作区初始化与既有小说接入

仅在以下情况读取本文档：

- 新小说需要建立 Spec 工作区；
- 工作区缺少主工作流要求的关键结构；
- 已有小说首次接入本工作流；
- 现有资料分散，尚未形成可维护的当前有效 Spec。

完成后回到 `novel-spec-workflow`，日常创作不重复读取。

## 接入类型

### 新小说

从作者当前已有构思建立最小可用工作区，不要求一次完善整部小说。

只确认当前无法绕开的上层内容：

- 期望体验；
- 整体基调；
- 创作边界；
- 已有故事主脉络及其中的候选部分。

高影响创作决策可进入 `grill-me`。不要一次询问人物模板、世界观清单、章节数量等可以后续自然形成的细节。

初始化结构：

```text
小说工作区/
├─ Spec/
│  ├─ 索引.md
│  ├─ 核心创作说明.md
│  ├─ 设定/
│  └─ 大纲/
│     └─ 总体大纲.md
└─ 正文/
````

`GRILL_ME_DISCUSSION.md` 仅在复杂跨轮讨论时临时创建。

不要机械创建空的人物、关系、世界、时间线、章节或任务文档。

按主工作流职责写入：

* `核心创作说明.md`：仅保存已确认的体验、基调和创作边界；
* `总体大纲.md`：保存当前已有剧情规划，并区分候选与已确认；
* `索引.md`：登记真实存在的 Spec 和当前进度；
* `设定/`：仅在已有具体事实需要归属时创建对应文档。

信息不足时允许留空或保留候选，不由 AI 补成正式事实。

## 既有小说接入

目标是整理出**可以继续创作的当前上下文**，不是重写小说、补齐全部设定或统一全部历史材料。

### 读取

选择最短路径：

1. 先读现有目录、索引、作者说明和明确标记的当前版本；
2. 再读已有大纲与设定；
3. 按需要读取相关已确认正文，确认实际发生的事件和状态变化；
4. 只有现有材料无法确定且会影响整理结果时，再询问用户。

不机械全文扫描。资料量大时，先建立导航和最小可用上下文，再逐步整理。

### 整理

* 用户明确指定的当前版本作为重要依据；
* 已确认正文用于确认实际写出的内容；
* 当前有效事实进入设定，未来规划进入大纲；
* 从正文反向整理时，区分文本明确事实与 AI 推断；
* 无法可靠判断的内容保留待确认；
* 不把旧版、废案、聊天记录或历史草稿混入当前有效 Spec。

接入时：

1. 盘点当前正式材料、正文位置和明显历史版本；
2. 创建或补全索引；
3. 整理核心创作说明；
4. 整理现有大纲并保留候选/已确认区别；
5. 将已有当前设定归入合适文档，不强制目录模板；
6. 保持正文在原有正文位置，不复制进 Spec；
7. 更新索引的进度和文档树；
8. 将仍需高影响判断的问题交给 `grill-me`。

## 历史迁移

正式 Spec 只维护当前有效版本，普通历史交给 Git 或现有版本管理。

如果旧内容仍实际影响当前大纲、正文或设定，可暂时记录：

```md
## 临时迁移说明

- 已废弃内容：...
- 尚受影响内容：...
- 待处理：...
- 清理条件：...
```

影响处理完成后删除，不演变成长期变更日志。

## 完成条件

满足以下条件即可结束 onboarding：

* 索引能够定位当前正式 Spec 和创作进度；
* 核心创作说明保存了目前已确认的长期约束；
* 大纲保存了当前已有剧情规划，并能区分候选与已确认；
* 已有设定有明确归属，没有机械创建无用文档；
* 正文位置和当前有效版本明确；
* 无法直接解决的高影响问题已有讨论入口。

随后回到主工作流。
