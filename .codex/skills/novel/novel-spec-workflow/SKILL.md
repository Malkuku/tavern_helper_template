# 小说 Spec 工作流

每部小说是独立工作区。Spec 保存长期创作约束、当前有效设定、剧情规划和导航；正文是正式创作产物。

本 Skill 只定义工作流，不保存具体小说事实。人物、世界、剧情和正文状态以当前工作区 Spec、已确认正文和用户明确决定为准。

工作区未初始化、关键 Spec 缺失或既有小说首次接入时，读取 `references/project-onboarding.md`。

## 基本结构

```text
小说工作区/
├─ Spec/
│  ├─ 索引.md
│  ├─ 核心创作说明.md
│  ├─ 设定/
│  └─ 大纲/
│     └─ 总体大纲.md
├─ 正文/
└─ GRILL_ME_DISCUSSION.md   # 仅复杂讨论时临时存在
````

按需增加 `Spec/创作任务/`、设定子文档或拆分大纲；不要默认创建快照、完整时间线、废案库、固定人物目录或复杂任务体系。

## Spec 职责

### 索引

`Spec/索引.md` 只保存：

* 已存在的 Spec 文档树及一句话用途；
* 当前大纲位置、正文位置、创作状态和独立任务入口。

不保存剧情摘要、人物状态、待办或其他 Spec 的副本。

已知文档位置时直接读取；需要了解结构时再读索引。正式 Spec 新增、删除、移动或重命名后同步索引。

### 核心创作说明

只保存长期作者约束：

* 期望体验；
* 整体基调；
* 明确创作边界。

故事事实、人物状态、世界观和剧情规划进入设定或大纲。

普通创作任务默认只读；只有用户明确改变这些长期约束时才修改。

### 设定

`Spec/设定/` 保存当前已经成立且仍有效的人物、关系、世界和其他故事事实。

按事实所属领域维护，不另建重复状态源。未来发展原则上写入大纲；需要记录设计方向时必须与当前事实明确区分。

### 大纲

`Spec/大纲/` 保存未来剧情规划，具体描述准备发生什么。

只区分：

* `候选`：已进入正式规划，但仍可修改；
* `已确认`：可作为正文依据。

优先维护现有文件；只有篇幅或剧情范围自然需要时才拆分。拆分后避免同一剧情重复保存，并同步索引。

### 正文

正文位于 Spec 外。

只有用户明确确认，或按项目约定进入有效正文链的内容，才能形成正式故事事实。

未确认草稿可以产生候选变化或影响分析，但不能自动改写正式 Spec。

正文承担普通事件记录；事件造成的长期变化回写设定，未来承接进入大纲。

### 创作任务

普通人设、大纲、写作、润色和单点审查直接执行。

只有跨多个文件、跨多轮、大范围修改或需要持续追踪时，才创建 `Spec/创作任务/`。

任务完成后把长期事实迁移到正式 Spec；无继续价值时删除或归档，避免成为第二套事实源。

## 事实归属

按问题类型确定依据：

* 创作体验、基调、边界 → `核心创作说明`
* 当前人物、关系、世界状态 → 对应设定
* 未来剧情 → 大纲
* 正式写出了什么 → 已确认正文
* 当前写作位置 → 索引和正文实际状态

发生冲突时先分类：

* 正文无合理依据违背已确认设计 → 修正文或标记重写；
* 正文形成合理新事实但 Spec 未同步 → 更新 Spec；
* 重要创作方向需要改变 → 进入 `grill-me`；
* 索引、路径或链接错误 → 直接修正。

不要建立机械的“正文 > 设定 > 大纲”总优先级。

## 读取与修改

按当前任务读取必要的 Spec、正文和讨论材料，不机械扫描整个工作区，也不询问文档中可以直接确认的事实。

修改重要设定前：

1. 读取目标设定及强关联内容；
2. 定向检索旧事实和相关对象；
3. 判断受影响的大纲、正文和其他设定。

不维护完整依赖图。

变化分为：

* **确定性更新**：路径、索引、进度、明确引用等，直接修改；
* **已确认决定**：用户确认的设定或剧情，写入正式 Spec；
* **AI 候选**：只进入候选、任务或讨论草稿；
* **冲突或高影响变化**：影响核心边界、重要人物逻辑或主线时，进入 `grill-me`。

不得把 AI 推断写成用户已确认事实。

## 任务收口

讨论和草稿阶段不持续修改正式 Spec。

方案或正文确认后统一收口：

1. 确认最终采用内容；
2. 判断形成或改变了哪些事实；
3. 更新对应设定；
4. 更新相关大纲及候选/已确认状态；
5. 必要时更新索引和正文进度；
6. 处理受影响的冲突或待复审项；
7. 删除已被正式工件承接的临时讨论和迁移说明。

结束时让用户知道：采用了什么、正式事实改了什么、还有哪些候选或未解决问题。

## 当前版本与历史

正式 Spec 默认只保存当前有效内容。

历史由 Git 承担，不长期保留删除线、旧版本、废案库或文档内变更日志。

只有旧内容仍影响当前事实时才临时保留迁移说明，并在影响处理完成后删除。

## 与 Grill Me 协作

以下情况进入 `grill-me`：

* 用户要求共同构思、比较或压力测试方案；
* 候选分支会显著改变故事结果；
* 正文与已有设计冲突且无法直接判断修改哪一侧；
* 变化影响核心创作说明、重要人物逻辑或主线。

`GRILL_ME_DISCUSSION.md` 只保存尚未进入正式 Spec 的讨论结果；稳定结论迁移后删除。

不要继续追问已经不影响主要创作决策、可以自然调整或能从现有材料判断的细节。
